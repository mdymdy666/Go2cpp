### 1.2 总架构图

```
业务（app/tools/tests）
   │
   ├── Process::Spawn ──► fork ──► ChildRun（只裸 syscall）
   │        │                        ├─ error pipe (O_CLOEXEC) 回传 errno
   │        │                        ├─ fd 重排（error→3，源 fd→≥10，dup2→0/1/2）
   │        │                        ├─ close_range(4..)
   │        │                        ├─ setsid/chdir/umask/setrlimit/setpriority/affinity
   │        │                        └─ execve
   │        ▼
   │   Process{pid, stdio fds, pty?}
   │        │
   │        ├── Wait/TryWait ──► pidfd_open + waitpid(WNOHANG) + poll；无 pidfd 时 1ms 轮询
   │        └── Kill/KillTree ─► kill(2)/进程组
   │
   ├── Run ──► Spawn + 写 stdin + FdChannel 泵 stdout/stderr + 超时/Kill
   │
   ├── ProcessPool ──► 固定 worker 线程 + 任务队列 + 每任务 Process
   │        └── Resize：target_workers + notify_all + 逐槽补位
   │
   ├── Supervisor ──► 事件循环（PollOnce/Run），重启/心跳/配额/条件
   │
   ├── File ──► read/write/readv/writev/sendfile（全部 EINTR 重试、非阻塞感知）
   │
   ├── Pty ──► openpty/forkpty；master 读写；EIO 映射关闭
   │
   └── Shm/Mq/Channel ──► 跨进程/跨 Fiber 数据面；AsyncIoBinding 负责 park
```

锁/边界：
- `Process` 的 fd 是进程级资源；父进程 close 顺序错误会误关别的线程刚 open 的 fd（PTY 三条流同 fd）。
- `ProcessPool` 一把 `mutex` 保护队列/槽位，`work_cv`/`space_cv`/`done_cv` 三个条件变量；worker 用 index 判断是否该退出。
- `Supervisor` 的事件循环单线程，`Impl::PollOnce` 内做超时/心跳/配额/条件评估。
- `Pty`/`FdChannel` 的 `pull` 用 `poll` + 裸 syscall，不经过 iostream。

### 1.3 复杂场景详解

#### 场景 A：`Process::Spawn` 一次带 PTY 的启动（14 步）

1. 业务填 `ProcessOptions`（`proc.hpp:417`）：argv/env/cwd/stdio 模式/pty/rlimits。
2. `Process::Spawn`（`proc.hpp:609`）→ `RealBackend::Spawn`（`proc.cpp:860`）。
3. 参数校验：nice 范围、sched policy、oom_score_adj、PTY 行列（`proc.cpp:867`-`:881`）。
4. 建 error pipe：`pipe2(..., O_CLOEXEC)`（`proc.cpp:1016`）；exec 成功时内核自动关写端。
5. 需要 PTY 时 `Pty::Open`（`pty.cpp`），三条流共用同一个从端 fd。
6. `fork()`（`proc.cpp:1070`）：子进程只复制调用线程。
7. 子进程 `ChildRun`（`proc.cpp:699`）：error fd 若 <3，先 `F_DUPFD_CLOEXEC` 到 `>=10`（`:704`）。
8. 三条源 fd 若 `<=2`，也复制到 `>=10`（`:714`）；否则 `dup2` 顺序会互相覆盖（`:734`）。
9. error fd `dup3(..., 3, O_CLOEXEC)`（`:738`），保证 `close_range(4,~0)` 不会关掉它（`:749`）。
10. `setsid`/`chdir`/`umask`/`setrlimit`（`:766`）/`setpriority`/`sched_setaffinity`/`oom_score_adj`/`setgroups/setgid/setuid` 依次执行；任何失败 `ChildFail(error_fd)`。
11. `execve`（`proc.cpp:813`）；失败写 errno 后 `_exit_group(127)`，不跑 atexit。
12. 父进程读 error pipe（`proc.cpp:1124`）：读到 4 字节 = 失败，EOF(0) = 成功。
13. 失败：`waitpid` 回收（`:1143`），返回 `kExecFailed + errno`；成功：构造 `SpawnedProcess`。
14. 父进程关闭子侧 fd：PTY 模式只 `ReleaseSlave` + close 一次（`proc.cpp:1100`）；非 PTY 按三条流分别关。

#### 场景 B：`Run` 一次命令（12 步）

1. `Run(options, input)`（`proc.hpp:736`）构造 stdio 管道模式的 `ProcessOptions`。
2. `Spawn` 成功，拿到 stdin/stdout/stderr 三个父侧 fd。
3. 父侧 fd 设非阻塞（`proc.cpp` Spawn 尾部），交给 `FdChannel`。
4. 有 `input` 时先写 stdin，写完 `CloseWrite`，子进程看到 EOF。
5. 循环 `Pull` stdout/stderr（`channel.hpp:317`）：`poll` + 裸 read。
6. 读到数据追加到输出缓冲，受 `max_output_bytes` 限制（超限 Kill/返回错误）。
7. `Pull` 返回 0 → EOF → `kClosed`；返回 `kTimeout` 继续等。
8. 主循环检查 `options.timeout`；超时 `Kill(SIGKILL)`（或 `Terminate` 宽限）。
9. `Wait` 收割（`proc.cpp:1192`）：pidfd + `waitpid(WNOHANG)`；无 pidfd 回退 1ms 轮询。
10. 合成 `RunResult{exit, stdout, stderr, timed_out}`。
11. 失败路径：Spawn 失败直接返回；写 stdin 的 EPIPE 表示子进程提前退出，不能当致命错误。
12. 退出后必须关闭三个通道，避免 fd 泄漏（`FdChannel` 析构/Close）。

#### 场景 C：`WritevAll` 一次短写（12 步）

1. 业务组 iovec 数组，总数可能 1024 段（`file.cpp:577` `kMaxIov`）。
2. `WritevAll`（`file.cpp:657`）先算总字节 `want`。
3. 快路径：`Writev(iov, iovcnt)`（`:672`）一次 syscall。
4. 返回值 `first == want` → 直接返回，不分配、不复制（`:671` 注释）。
5. `first < 0` → 返回 0，`last_error` 保留 errno。
6. `first == 0` → 写路径按失败处理，返回 0。
7. 短写：复制一份 `vector<iovec> rest`（`:683`）。
8. `AdvanceIov(rest, iovcnt, total)`（`:591`）：跨段扣减 `consumed`，必要时前移 `iov_base`、减小 `iov_len`。
9. 循环 `Writev(rest+index, iovcnt-index)`（`:686`），每次累加并再次 `AdvanceIov`。
10. 某次返回 `<=0` → 停止（0 在写路径按失败），返回已写字节。
11. `bad_alloc` → 置 `ENOMEM`，返回已写字节。
12. 调用方必须用返回值判断「是否写全」，不能假设 `WritevAll == want`。

#### 场景 D：`CopyTo` 的 sendfile 路径（10 步）

1. `CopyTo(dst, &copied, max_bytes)`（`file.cpp:745`）。
2. 检查两个 fd 有效；`limit = max_bytes==0 ? 无上限 : max_bytes`。
3. `offset = Tell()`；`have_offset = offset >= 0`。
4. 循环：`chunk = min(limit-total, 1 MiB)`（`:771`）。
5. `sendfile(dst, src, have_offset ? &offset : nullptr, chunk)`（`:775`）。
6. `result < 0`：取 errno；只有 `total==0` 且 errno ∈ {EINVAL,ENOSYS,EXDEV,EOPNOTSUPP,ENOTSUP} 才 `fallback`（`:781`）。
7. 其它错误：返回 `kIoFailed` + `*copied = total`（已拷的不回退）。
8. `result == 0` → EOF，跳出。
9. 正常结束：`have_offset` 时 `Seek(offset, SEEK_SET)`（`:806`）补上 in_fd 偏移。
10. 回退路径：64 KiB 缓冲 `Read`+`Write` 循环，语义一致但多一次用户态拷贝。

#### 场景 E：`ProcessPool` 缩容后再提交（12 步）

1. `Start(options)`（`pool.hpp:131`）建 `workers` 个线程，`WorkerLoop(index)`（`pool.cpp:250`）。
2. `Submit(task)`（`pool.cpp:116` `Enqueue`）拿 mutex，检查 `running`，入队。
3. `work_cv.notify_all()`（`pool.cpp:161`）：不能 `notify_one`（缩容后可能唤醒将被裁的 worker）。
4. worker 醒来，`wait` 谓词检查 `!queue.empty() && index < target_workers`（`:261`）。
5. 不满足谓词的 worker 继续睡；满足的取任务。
6. `Resize(smaller)`（`:326`）先 `target_workers.store(workers)`（`:340`）。
7. `index >= target` 的 worker 在队列空时自行退出（`:279`），把槽位腾空并登记到 `retired`。
8. `Resize(larger)` 逐槽检查 `threads[slot].joinable()`，补新线程（`:349` 起）。
9. 只看 `alive_workers` 会漏掉「刚退出线程留下的空槽」，导致永久少一个 worker。
10. `SubmitAndWait`（`pool.hpp:145`）用 `Slot` + `done_cv` 等结果；超时返回错误但任务可能仍在跑。
11. `Shutdown`（`pool.hpp:156`）先 `CancelQueueLocked` 把未执行任务标错，再等 `stats.running==0`，超时 Kill。
12. 退出后 join `retired`；线程不能 join 自己，所以登记与 join 分离。

### 1.4 关键不变量

| # | 不变量 | 位置 | 破了会怎样 |
|---|---|---|---|
| 1 | fork 后子进程只调裸 syscall，不 malloc/不加锁 | `proc.cpp:6` | 多线程 fork 后死锁在已不存在的锁上 |
| 2 | error pipe 必须 `O_CLOEXEC`，父读 EOF=成功 | `proc.cpp:1016`/`:1124` | 无法区分 exec 成功/失败，或 fd 泄漏给子进程 |
| 3 | error fd 必须搬到 `>=10`、最终固定 3，close_range 从 4 开始 | `proc.cpp:704`/`:738`/`:749` | 误关 error fd（错误静默丢失）或覆盖 stdio |
| 4 | PTY 三条流是同一个 slave fd，父进程只 close 一次 | `proc.cpp:1094`/`:1100` | 并发 Spawn 误关他人 fd（EBADF/通道被 closed） |
| 5 | master 对端全关时 read 返回 EIO，映射为 kClosed | `pty.hpp:18`/`pty.cpp:333` | 把正常退出当 I/O 错误 |
| 6 | `writev` 可能部分写，必须用推进后的 iovec | `file.cpp:572`/`:591` | 重发导致数据重复或丢尾 |
| 7 | `sendfile` 显式 offset 不移动 in_fd 偏移，必须 Seek 回写 | `file.cpp:806` | 后续 Read 从错位置继续 |
| 8 | 已拷过字节后不允许回退 read+write | `file.cpp:781` | 重复拷贝/丢失，`copied` 不可信 |
| 9 | Pool 的等待谓词含 `index < target_workers`，必须 notify_all | `pool.cpp:155`/`:161`/`:261` | 任务滞留到 SubmitAndWait 超时 |
| 10 | `Resize` 逐槽补位，不能只看 alive_workers | `pool.cpp:347` 注释 | 永久少 worker |

## 第二部分 · 分：逐块细讲

### 2.1 进程创建：`Process` / `Spawn`（`proc.cpp`）

**职责**：把「fork + 重排 fd + execve + 错误回传」封成一个 `Process`。

**数据结构**：`ProcessOptions`（`proc.hpp:417`）含 `argv/env/cwd/stdin_mode/stdout_mode/stderr_mode/pty/rlimits/nice/affinity/sched/oom_score_adj/uid/gid/groups`；`ChildPlan`（`proc.cpp` 内）是 fork 前准备好的只读快照，子进程只读它。

**关键函数**：`RealBackend::Spawn`（`:860`）校验参数、建管道、fork；`ChildRun`（`:699`）是 `[[noreturn]]` 的纯 syscall 序列；`ChildFail(error_fd)` 写 errno 后 `_exit_group(127)`；`WaitFor`（`:1192`）收割。

**失败路径**：pipe/fork 失败直接返回 errno；子进程任意一步失败写 error pipe；execve 失败同样；父进程读到 4 字节 → `kExecFailed`。**已知限制**：error fd 重排逻辑依赖 `F_DUPFD_CLOEXEC` 可用；`close_range` 不可用时按 `close_limit` 循环（可能很慢）。

**典型误用**：在 `Spawn` 后忘记读 error pipe（会阻塞/漏错误）；在子进程回调里用 `std::string`。

### 2.2 `Run` 与输出泵

**职责**：一次性命令执行：写 stdin、收 stdout/stderr、超时、Kill。

**关键点**：`Run` 用管道模式而非 PTY；stdin 写完要 `CloseWrite` 让子进程看到 EOF；读端用 `FdChannel::Pull`（`channel.hpp:317`），0=EOF、`kTimeout` 继续；`max_output_bytes` 超限要 Kill 并标记错误。

**失败路径**：Spawn 失败、写 stdin 的 EPIPE（子进程提前退出，通常不致命）、超时（Kill 后仍需 Wait 收割，否则僵尸）。

**典型误用**：只读 stdout 不读 stderr → 子进程写满 stderr 管道阻塞；超时后不 Wait → 僵尸累积。

### 2.3 批量 syscall：`Readv/Writev/ReadvAll/WritevAll`

**职责**：把 N 次小读写压成 1 次 syscall；难点是部分推进。

**数据结构**：`struct iovec` 数组，`iovcnt ∈ [1,1024]`（`file.cpp:577`）。

**关键函数**：`AdvanceIov`（`:591`）是核心；`WritevAll`（`:657`）快路径不分配、慢路径复制；`ReadvAll`（`:701`）EOF 返回已读（`:731`）。

**失败路径**：`nullptr`/`0`/`1025` → `EINVAL`；全零 iovec → 返回 0 不报错；`bad_alloc` → `ENOMEM` + 已处理字节。

**典型误用**：`Writev` 返回值当「全写」；`ReadvAll` 把 0 当错误（其实是 EOF）。

### 2.4 `CopyTo` / sendfile

**职责**：文件到文件的零拷贝（内核态搬运）。

**关键点**：显式 offset 不推进 in_fd；0=EOF；只在 total==0 时回退；1 MiB 分块限制单次停顿；`max_bytes` 硬上限。

**失败路径**：坏句柄 `kInvalidHandle/EBADF`；`sendfile` 不支持的文件系统/非 socket 目标 → 回退 read+write；慢读导致部分写，循环继续。

**典型误用**：用 sendfile 做 TLS/压缩（需要用户态改写）；忘记 Seek 回写。

### 2.5 `ProcessPool`

**职责**：固定 worker 线程池执行短命令，限制并发与队列。

**数据结构**：`Impl`（`pool.cpp:34` 起）含 `queue`、`threads`、`retired`、`alive_workers`、`running_pids`、`target_workers`、三个 cv。

**状态机**：

| 状态 | 事件 | 动作 |
|---|---|---|
| 未 Start | Submit | `kNotRunning` |
| running | Submit | 入队 + notify_all |
| worker | 队列非空且 index<target | 取任务、Execute |
| worker | index>=target 且队列空 | 登记退出到 retired |
| Resize 小 | target 降低 | 多余 worker 自行退出；不 join 自己 |
| Resize 大 | target 提高 | 逐槽补位（joinable 判断） |
| Shutdown | running=false | CancelQueue + 等 running==0 + 超时 Kill |

**失败路径**：`SubmitAndWait` 超时（任务可能还在跑）；`Resize` 后空槽漏补（只看 alive_workers 就会）；worker 不能 join 自己。

**典型误用**：缩容后用 `notify_one`；把 `alive_workers` 当线程数。

### 2.6 `Supervisor`

**职责**：托管多个进程，按策略重启/心跳/配额/条件终止。

**关键行**：`Supervisor::Impl`（`supervisor.cpp:187`）、`Spawn/Add`（`:379`/`:389`）、`PollOnce`（`:792`）、`WaitForEvents`（`:742`）、`Run`（`:858`）、`EvaluateQuota`（`:672`）、`TriggerTerminate`（`:582`）。

**状态机**：启动 → 运行（心跳/输出/配额）→ 退出（OnExit 事件）→ 按策略重启或终止；`Stop(grace)` 先 SIGTERM，宽限后 SIGKILL。

**失败路径**：子进程无法 reap（ECHILD）；输出缓冲无界（由 `max_output_bytes` 限制）；Stop 时事件循环仍在跑。

**典型误用**：在事件回调里阻塞；忘记 `PollOnce` 导致心跳/超时不触发。

### 2.7 PTY

**职责**：伪终端：master 端读写、窗口大小、从端交给子进程。

**关键点**：`Pty::Open` 内部 `posix_openpt/grantpt/unlockpt`；`forkpty` 或 `openpty` 后 `setsid` + `TIOCSCTTY`；`ReleaseSlave`（`pty.cpp:193`）转移所有权；master 对端全关时 `read` 返回 `EIO`（`pty.cpp:333` 映射 `kClosed`）；`Resize` 用 `TIOCSWINSZ` 并给从端发 SIGWINCH。

**失败路径**：`openpty` 失败（ENODEV/EMFILE）；slave 已关闭时写返回 EPIPE；master 关闭时从端收到 SIGHUP/EIO。

**典型误用**：父进程按三条流各 close 一次（见不变量 4）；把 EIO 当错误。

### 2.8 Shm / Mq

**职责**：跨进程共享内存与消息队列；`ShmChannel`/`MqChannel` 提供统一 `MessageChannel` 接口。

**关键点**：`Shm` 用 `shm_open`+`ftruncate`+`mmap`；名字需要 `Unlink`（`shm.hpp:119`），否则残留 `/dev/shm`；`SharedRingBuffer` 用原子 head/tail + eventfd/pipe 通知。`Mq::Send/Receive`（`mq.hpp:132/137`）在满/空时通过 `WaitWritable/WaitReadable` park Fiber；`SendBatch/ReceiveBatch`（`:140/145`）合并。

**失败路径**：`shm_open` EEXIST/EACCES；`mq_send` EAGAIN（非阻塞）；接收超时；Fiber 取消时唤醒路径。

**典型误用**：创建者不 Unlink 导致泄漏；把 Shm 当持久存储（重启即失）。

### 2.9 Channel 与 io_capability

**职责**：`FdChannel` 把「poll + 裸 read/write」封成带缓冲的消息通道；`AsyncIoBinding` 把等待挂到 IOManager（Fiber 感知）。

**关键行**：`FdChannel`（`channel.hpp:298`）、`Pull`（`:317`）、`CloseRead/CloseWrite`（`:362/363`）；`AsyncIoBinding::WaitReadable/WaitWritable`（`io_capability.hpp:156/158`）。

**失败路径**：对端关闭 `kClosed`（不是 EOF 0）；写 EPIPE → `kChannelClosed`；`Wait*` 只能在 manager 管理的 Fiber 中调用。

**典型误用**：在非 Fiber 线程调 `WaitReadable`；把 `kClosed` 当超时重试。

### 2.12 场景 F：Shm/Mq 一次跨进程消息（12 步）

1. 创建方 `Shm::Create(name,size)`：`shm_open(O_CREAT|O_RDWR)` + `ftruncate` + `mmap`。
2. 初始化 `SharedRingBuffer` 的 head/tail/容量/魔法字段。
3. 打开方 `Shm::Open(name)`：`shm_open` + 同尺寸 `mmap`。
4. 双方用 eventfd 或 pipe 做「有新数据」通知（`ShmChannel` 封装）。
5. `Send(payload)`：检查剩余空间，拷贝到环形缓冲，更新 tail（release）。
6. 通知对端（写 eventfd/pipe）。
7. 接收方 `Pull/WaitReadable`（`io_capability.hpp:156`）被唤醒。
8. `Receive`：读 head，拷贝出 payload，更新 head（release）。
9. 满/空时 `Mq::Send/Receive` 通过 `WaitWritable/WaitReadable` park Fiber，而不是忙等（`mq.hpp:47`-`:48`）。
10. 批量：`SendBatch/ReceiveBatch`（`mq.hpp:140/145`）合并多次操作。
11. 关闭：`Close` 解除映射；创建方 `Unlink`（`shm.hpp:119`）删除名字，否则 `/dev/shm` 残留。
12. 失败路径：`shm_open` EEXIST/EACCES、`mmap` ENOMEM、对端崩溃后 ring 状态不一致（需要 magic/版本校验或重建）。

### 2.13 改这个模块前的检查清单

1. 动 fork 之后的代码：只能裸 syscall；不要引入 `std::string`/`malloc`/锁/异常。
2. 动 fd 重排：保持「error fd → 3、源 fd → ≥10、dup2 → 0/1/2、close_range 从 4」的顺序。
3. 动 PTY：三条流同 fd，父进程只 close 一次；EIO 必须映射关闭。
4. 动批量 I/O：任何部分写都要用 `AdvanceIov` 推进，不能重发已写段。
5. 动 sendfile：显式 offset 必须 Seek 回写；只在 total==0 时回退。
6. 动 Pool：等待谓词含 `index < target_workers`，唤醒必须 notify_all；Resize 逐槽补位。
7. 动 Supervisor：事件循环里不要阻塞；Stop 的 grace 到期必须升级 SIGKILL。
8. 动 Shm/Mq：创建者负责 Unlink；Fiber 等待要能被取消。
9. 任何 syscall 包装都要处理 EINTR；非阻塞 fd 要处理 EAGAIN。
10. 性能结论必须给命令/环境（2.10），不抄文档数字。
