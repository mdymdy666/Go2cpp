# 并发 + 网络模块审查顺序（从底到顶）

> 用途：用户今天审查并发与网络两个模块。**从底层原语往上层应用**逐层审——底层错，上层全错。
> 每步标注：**文件**、**为什么要这一层**、**审查关注点**、**预估**（按 15–20 分钟/步）。

---

## 一、并发模块（12 步，约 3.5–4 小时）

## 三、建议节奏

| 时段 | 内容 |
|---|---|
| 上午 | 并发第 1–8 层（原语 + 锁 + 同步） |
| 下午 | 并发第 9–16 层（调度器 + fiber + channel）+ 网络第 1–5 层 |
| 傍晚 | 网络第 6–11 层（IO + hook + HTTP） |
| 晚上 | 网络第 12–14 层（HTTP/2、WS、HTTP/3） |

## 四、每层通用检查清单（丢唤醒 + 资源）

- [ ] 所有 `condvar.wait` 的谓词：`atomic` 或同锁保护 + `while`；
- [ ] 所有 `notify_*`：是否在锁内（不在锁内必须能证明无窗口）；
- [ ] 所有 `wait`：是否带超时或 cancel；
- [ ] 所有 fd/内存/线程：是否有明确的释放点；
- [ ] 所有 `[[nodiscard]]`：调用方是否检查。
