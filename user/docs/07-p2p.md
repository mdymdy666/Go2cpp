# P2P 与 NAT 穿透（交接文档）

> **定位**：两端各自在 NAT/防火墙之后时，建立一条**尽量直连、失败降级中继**的 UDP 数据通道；
> 附带可独立部署的 STUN echo 服务器与简化 TURN 中继服务器。
> **源码**：`include/go2cpp/p2p/`、`src/p2p/`　**构建**：`cmake/Go2CppP2P.cmake`（`-DGO2CPP_WITH_P2P=ON`，默认 ON）
> **测试**：`tests/p2p/`（`p2p_test_stun` / `p2p_test_p2p` / `p2p_test_tcp_punch` /
> `p2p_test_p2p_interprocess`，基准 `p2p_bench` 不注册 ctest）
> **设计全文**：[p2p-nat-traversal.md](../../docs/modules/p2p-nat-traversal.md)（原理、部署、参数建议）

## 1. 这个模块是什么

一句话：**用 STUN 问出「我在公网长什么样」，把地址通过信令告诉对端，双方同时朝对方发包把 NAT 打穿；
打不穿就走中继。**

它解决「没有公网 IP 的两台机器怎么直连 UDP」：不引入 WebRTC 栈、不依赖 `go2cpp_runtime` 与
`go2cpp::network`（因此不会被 Fiber/syscall hook 影响），只用 libc + pthread + Linux socket。

| 能力 | 实现位置 | 状态 |
|---|---|---|
| STUN Binding（RFC 5389 子集，含 XOR-MAPPED-ADDRESS / CHANGE-REQUEST） | `stun_message.*`、`stun_client.*` | 完整可用 |
| NAT 类型检测（RFC 3489 四类 + OpenInternet） | `stun_client.hpp` 的 `NatTypeDetector` | 需双 IP 才能区分 Full Cone |
| STUN echo 服务器（单线程 poll，最多 4 socket） | `stun_server.*` | 可独立部署 |
| UDP 打洞（并行检查、重发、超时） | `p2p_channel.cpp` | 完整可用 |
| TCP 同时打开 | `tcp_punch.*` | 仅 IPv4，部分 NAT 组合有效 |
| ICE 简化（host/srflx/prflx/relay + 优先级 + 第一个成功） | `candidate.*`、`p2p_channel.cpp` | **无 controlling/controlled 与 nomination** |
| TURN 简化（Allocation/Send/Data/Refresh/Release） | `turn.hpp`、`relay_protocol.cpp` | 可跑，但**无鉴权、无权限表** |

边界一句话：**「尽力直连 + 兜底中继」，不是 RFC 5766 TURN，也不是完整 ICE**；没有加密、没有可靠传输、
没有拥塞控制。

## 2. 架构 / 数据流

### 2.1 建连时序

```
       A                                                     B
       │  信令（IM / 自建 TCP / LoopbackSignaling）            │
       │◄──────────── 交换候选列表（文本）──────────────────►│
       │                                                     │
 ┌─────┴──────────────┐                            ┌─────────┴──────────┐
 │ GatherCandidates() │                            │ GatherCandidates() │
 │  host  ← 网卡枚举   │                            │  host              │
 │  srflx ← STUN      │◄──── STUN Binding ────────►│  srflx ← STUN      │
 │  relay ← Allocate  │                            │  relay             │
 └─────┬──────────────┘                            └─────────┬──────────┘
       │  对每个候选对并行发 Binding 检查（check_interval 重发）│
       ▼                                                     ▼
   直连成功 ──是──► Connected ──数据帧 G2PD──► Connected ◄──是── 直连成功
       │否                                                   │否
       ▼                                                     ▼
   中继 Allocate 成功 ──是──► Relayed ◄──是── 中继 Allocate 成功
       │否                                                   │否
       ▼                                                     ▼
     Failed                                               Failed
```

### 2.2 状态机（`P2PState`）

```
  Idle ──GatherCandidates()──► Idle（候选就绪）
    │
    │ Connect(timeout)
    ▼
Connecting ──直连检查成功──► Connected
    │                          │ 直连失败但中继成功 / 收到中继检查成功
    │                          ▼
    └────────────────────► Relayed
    │
    │ 全部失败
    ▼
 Failed ──Close()──► Closed（任意状态都可 Close）
```

`Send`/`Recv` 只在 `Connected`/`Relayed` 下工作；`Close()` 会释放中继 allocation。

### 2.3 数据帧（12 字节头 + payload）

```
 0        4        5        6        8                12
 +--------+--------+--------+--------+----------------+------------------+
 | "G2PD" | ver(1) | type   | length | sequence (4)   | payload ≤1200B   |
 +--------+--------+--------+--------+----------------+------------------+
   type: 1=data  2=keepalive  3=keepalive-ack
```

`length` 必须与数据报剩余长度**严格相等**（防截断/拼接）；单包上限 `kP2PMaxPayload = 1200`，
避免 1500 MTU 下的 IP 分片。更长的消息由上层分片。

### 2.4 线程模型（交接重点）

| 组件 | 线程 | 说明 |
|---|---|---|
| `GatherCandidates()` / `Connect()` | 调用方 | 同步阻塞，不可并发调用 |
| `Send()` / `Recv()` | 可分别在不同线程 | 一发送一接收是允许的；状态与统计有互斥量 |
| keepalive | 无后台线程 | **由 `Recv()` 驱动**：每次进入检查是否该发心跳 |
| `StunServer` / `RelayServer` | 各自 1 条 poll 线程 | `Start()` 起，`Stop()` join |

只发不收的场景必须周期性调 `Recv(0ms)` 轮询，否则 NAT 映射可能过期——这是最容易踩的坑。

## 3. 对外 API（关键接口）

### 3.1 `P2PChannel`（唯一对外入口）

```cpp
class P2PChannel {
public:
    explicit P2PChannel(P2PConfig config);

    std::vector<Candidate> GatherCandidates();        // host + srflx + relay，阻塞
    void AddRemoteCandidate(const Candidate& candidate);
    bool Connect(std::chrono::milliseconds timeout);  // 0 = 用 connect_timeout
    bool Send(const void* data, std::size_t length);  // ≤1200B，未连接返回 false
    std::size_t Recv(void* buffer, std::size_t capacity, std::chrono::milliseconds timeout);
    bool IsRelayed() const;
    bool IsConnected() const;
    P2PState state() const;
    Endpoint LocalEndpoint() const;
    Endpoint PeerEndpoint() const;
    std::vector<Candidate> LocalCandidates() const;
    std::vector<Candidate> RemoteCandidates() const;
    P2PStats Stats() const;
    std::string LastError() const;
    void Close();
};
```

`Recv` 返回语义：`> 0` 字节数、`0` 超时/未连接、超过容量时**截断并返回 capacity**。
控制帧（keepalive/STUN）在内部消化，不会返回给调用方。

### 3.2 `P2PConfig` 关键字段

```cpp
Endpoint bind_endpoint = Endpoint::Wildcard(0);
std::vector<Endpoint> stun_servers;          // 空 = 只做局域网直连
Endpoint turn_server;                        // 无效 = 不启用中继降级
Signaling* signaling = nullptr;              // 空 = 必须手动 AddRemoteCandidate
std::shared_ptr<DatagramTransport> transport;// 注入可模拟 NAT（测试用）
std::chrono::milliseconds gather_timeout{800};
std::chrono::milliseconds connect_timeout{5000};
std::chrono::milliseconds check_interval{100};
std::chrono::milliseconds keepalive_interval{15000};   // 0 = 关闭
std::chrono::milliseconds peer_timeout{30000};
bool gather_host_candidates = true;
bool gather_loopback_candidates = true;
bool enable_relay = true;
bool auto_exchange_candidates = true;
std::size_t max_local_candidates = 16;
```

### 3.3 STUN 与 NAT 检测

```cpp
class StunClient {
    StunClient(DatagramTransport* transport, Endpoint server);
    std::optional<Endpoint> Binding(std::chrono::milliseconds timeout, std::string* error = nullptr);
    std::optional<StunExchangeResult> Exchange(const StunMessage& request, std::chrono::milliseconds);
};

enum class NatType : std::uint8_t { kUnknown, kOpenInternet, kFullCone,
                                    kRestrictedCone, kPortRestrictedCone, kSymmetric };
class NatTypeDetector {
    NatDetectionResult Detect();   // 严格按 RFC 3489 §10.1 顺序：I→II→III→IV
};
```

`Detect()` 的 **Test IV 必须放最后**：先做会让 NAT 把备用服务器记入过滤表，Port Restricted 被误判成
Full Cone。这个顺序在四种模拟 NAT 下都验证过。

### 3.4 服务器端

```cpp
class StunServer {                       // 可独立部署
    explicit StunServer(StunServerConfig config = {});
    bool Start(std::string* error = nullptr);
    void Stop();
};
class RelayServer {                      // 简化 TURN
    explicit RelayServer(RelayServerConfig config = {});
    bool Start(std::string* error = nullptr);
    void Stop();
    RelayServerStats stats() const;
};
class RelayClient {
    RelayClient(DatagramTransport* transport, RelayClientConfig config);
    bool Allocate(std::string* error = nullptr);
    bool Refresh(std::string* error = nullptr);
    void Release();
    bool SendTo(const Endpoint& peer, const void* data, std::size_t length);
};
```

`StunServerConfig` 支持 `primary` + 备用地址（4 个 socket），用于 `CHANGE-REQUEST` 的「换 IP」与
「换端口」两种响应；单 IP 部署时 Full Cone 检测退化为 `Unknown`，不会瞎猜。

### 3.5 候选、TCP 打洞与信令

```cpp
enum class CandidateType : std::uint8_t { kHost, kServerReflexive, kPeerReflexive, kRelay };
struct Candidate {
    CandidateType type = CandidateType::kHost;
    Endpoint endpoint;
    std::uint32_t priority = 0;              // host > srflx > prflx > relay
    static std::optional<Candidate> Parse(std::string_view line, std::string* error = nullptr);
};

class TcpPuncher {                            // TCP simultaneous open，仅 IPv4
    static std::unique_ptr<TcpPuncher> Bind(const Endpoint& local, std::string* error = nullptr);
    bool Send(const void* data, std::size_t length);
    int  Recv(void* buffer, std::size_t capacity, std::chrono::milliseconds timeout);
};

class Signaling {
    virtual bool Send(const std::string& payload) = 0;
    virtual int  Recv(std::string* payload, std::chrono::milliseconds timeout) = 0;
};
static std::pair<std::unique_ptr<LoopbackSignaling>, std::unique_ptr<LoopbackSignaling>>
LoopbackSignaling::CreatePair();              // 进程内测试/演示
```

`Signaling` 只定义「一条可靠、有序、双向的消息通道」，IM/WebSocket/自建 TCP 都能实现它。

## 4. 最小用法（可编译示例）

同进程两条通道，用 `LoopbackSignaling` 交换候选并打通（生产环境换成真实信令）：

```cpp
#include "go2cpp/p2p/p2p_channel.hpp"
#include "go2cpp/p2p/signaling.hpp"
#include <iostream>
#include <thread>

int main() {
    auto [sig_a, sig_b] = go2cpp::p2p::LoopbackSignaling::CreatePair();

    go2cpp::p2p::P2PConfig ca;  ca.signaling = sig_a.get();
    ca.gather_loopback_candidates = true;      // 本机回环地址也算 host 候选
    go2cpp::p2p::P2PConfig cb;  cb.signaling = sig_b.get();
    cb.gather_loopback_candidates = true;

    go2cpp::p2p::P2PChannel a(ca), b(cb);
    a.GatherCandidates();
    b.GatherCandidates();

    std::thread ta([&] { a.Connect(std::chrono::milliseconds(3000)); });
    std::thread tb([&] { b.Connect(std::chrono::milliseconds(3000)); });
    ta.join();  tb.join();
    if (!a.IsConnected()) return 1;

    const char msg[] = "hello-p2p";
    if (!a.Send(msg, sizeof(msg))) return 1;                 // ≤ kP2PMaxPayload(1200)
    char buf[1200];
    std::size_t n = b.Recv(buf, sizeof(buf), std::chrono::milliseconds(1000));
    std::cout << "B received " << n << " bytes, relayed=" << b.IsRelayed() << "\n";
    a.Close();  b.Close();
    return n == sizeof(msg) ? 0 : 1;
}
```

链接：`target_link_libraries(app PRIVATE go2cpp::p2p)`。要点：`Connect()` 是阻塞的，双方必须
**并发**发起（Port Restricted NAT 只放行「内部曾发过包的目标」），示例里用两条线程。

## 6. 性能数据

**本模块没有 asm 级实测**——`docs/reports/` 下没有 `asm-p2p.md`，也没有对 `p2p_channel.cpp` 做过
objdump/下限分析。下表只来自模块文档的压测，口径是「WSL2 回环、Release、单核调度」，**不是**指令级证据：

| 指标 | 结果 |
|---|---|
| STUN Binding（1000 次） | 1000/1000 成功，≈10000 req/s，P50=0.09ms、P95=0.16ms、P99=0.20ms |
| 直连 1KB × 20000 包 | 100% 到达，≈190–210MB/s，P50≈0.02ms、P95≈0.10ms、P99≈0.13ms |
| 直连 RTT（1000 轮） | P50=0.010ms、P95=0.011ms、P99=0.018ms |
| 中继 512B × 5000 包（10k pps 限速） | 100% 到达，≈2.24MB/s，P50=0.12ms、P95=0.21ms、P99=0.26ms |
| 中继 RTT（200 轮） | P50=0.21ms、P95=0.38ms、P99=0.46ms |

来源：[p2p-nat-traversal.md](../../docs/modules/p2p-nat-traversal.md) §5.3。中继吞吐比直连低两个
数量级：数据要经「客户端 → relay socket → listen socket → 客户端」两次用户态转发且单线程 poll，
洪泛会打满 `net.core.rmem_max`（208KB）；基准按 10k pps 限速测的是可持续吞吐。

## 7. 边界与已知限制

1. **对称 NAT 打不通**：每个目标分配不同外部端口，STUN 得到的映射端口对打洞包无效，只能走中继。
   本模块会自动降级，代价是延迟与服务器带宽。
2. **UDP 被完全封锁**时打洞与中继都不可用；TCP 同时打开只在部分 NAT/防火墙组合有效且平台不一致。
   企业网可能需要 HTTP 代理/WebSocket 隧道（不在本模块范围）。
3. **STUN 无鉴权**：任何能访问服务器的人都能查映射地址；生产应限制来源网段，别当身份来源。
4. **TURN 无鉴权、无权限表**：知道 relay 地址就能发包、消耗带宽；只能部署在可信内网或用防火墙 + 配额。
5. **ICE 简化**：没有 controlling/controlled 与 nomination，理论上第三方在正确时机发合法 Binding
   检查可能插入连接；数据面**没有加密**，安全敏感场景必须自己加端到端加密与身份校验。
6. **无可靠传输**：不重传、不做拥塞控制、无 FEC；弱网下把 `P2PChannel` 当链路层，可靠交给上层。
7. **单路径**：连接成功后只用一个 peer 地址，对端换网/换端口即失效，必须重新 `Connect`。
8. **IPv6 不完整**：`TcpPuncher` 与测试用的 `MockNat` 只支持 IPv4；IPv6 下通常无 NAT，host 直连即可。

## 9. 交接注意

- **`Connect()` 必须双方并发**：单边调用必然超时（NAT 只放行内部发过包的目标）。集成测试用两条线程
  或两个进程，别在一个线程里先 A 后 B。
- **`Recv()` 是 keepalive 的驱动器**：只发不收会让 NAT 映射过期、对端判定失联。任何「只上传」的用法
  都要周期性 `Recv(0ms)` 轮询。
- **`P2PConfig::signaling` 是非拥有裸指针**：`Signaling` 生命周期必须比 `P2PChannel` 长，否则
  `Connect()` 里会悬空访问。
- **候选交换是文本协议**：`Candidate::Parse` 对非法输入整体失败；改格式要同时改信令两端。
- **`NatTypeDetector` 的测试顺序不可动**：Test IV 必须最后做，否则 Full Cone 误判（见 §3.3）。
- **未完成事项**：MESSAGE-INTEGRITY/FINGERPRINT、完整 TURN（RFC 5766）鉴权与权限表、ICE nomination、
  IPv6 的 TCP 打洞、多路径/迁移。逐条见 [p2p-nat-traversal.md](../../docs/modules/p2p-nat-traversal.md) §6。
