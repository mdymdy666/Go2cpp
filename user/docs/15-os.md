# os 模块（交接文档）

> ⚠️ **本文性能数字均为历史快照（2026-11-04 前，未按现行口径复跑）**：
> 文中的吞吐（MiB/s、GB/s）、倍率（×）、延迟（ns/µs/ms）与分位（p50/p99）数字，来自当时的交接记录，

## 1. 这个模块是什么

`go2cpp::os` 把 Go `os`/`os/exec`/`os/signal` 背后的 POSIX 能力收拢成一套 RAII 封装，
分成两块：

1. **文件/目录**：`File`（普通文件句柄）、`ReadFile`/`WriteFile`、环境变量、`ReadDir`/
   `MkdirAll`/`RemoveAll`/`Readlink`/`Symlink`/`StatPath`、`Args`/`Exit`；
2. **多进程/IPC**：`Process`/`Spawn`/`Run`、`Pipe`/`SocketPair`、`MessageChannel`（G2CF 帧）、
   `SharedMemory`/`RingBuffer`/`ShmChannel`、`MessageQueue`/`MqChannel`、`Pty`、
   `Supervisor`、`ProcessPool`、`IoCapability`/`AsyncIoBinding`。

**核心设计前提（最容易踩的坑）**：普通文件 IO 在内核里同步完成、不会 `EAGAIN`，所以本模块
**全部 fd 级读写走裸 `syscall(SYS_*)`，不经过 `go2cpp_hook`**，行为与 Go 的 `os.File` 一致。
直接后果：

- **在 Fiber 里调用本模块的阻塞 API 会阻塞它所在的 worker 线程（M）**；
- 需要协程友好的等待，必须显式 `EnableAsync(IOManager*)`（仅对 pollable fd 有效），
  或把调用放到独立线程；
- `File` **只接受普通文件**：`Adopt` socket/FIFO/eventfd 会返回 `kIsSocket`/`kNotRegularFile`，
  因为绕过 Hook 的 `read` 会把 M 卡死。

## 2. 架构 / 数据流

### 2.1 分层

```
supervisor / pool  ──►  proc（fork/exec/wait4/信号/Run 输出泵）
      │                    │
      ▼                    ▼
  channel（FdChannel / Pipe / SocketPair / G2CF 帧 / FlowBuffer / ChannelRegistry）
      │                    │
      ├──► shm（SharedMemory / RingBuffer / ShmChannel）
      ├──► mq（MessageQueue / MqChannel）
      ├──► pty（posix_openpt / TIOCSWINSZ）
      └──► io_capability（fd 分类 / AsyncIoBinding）
                              │
                        file / dir（普通文件、路径、环境变量）
```

依赖方向单向向下；`file`/`dir` 不依赖任何 IPC 子层。

### 2.2 fork/exec（proc）

```
父进程：整理 ChildPlan（stdio/cwd/uid/gid/rlimits/亲和性）
        → 创建 O_CLOEXEC 错误管道
        → fork
子进程：dup2 stdio → setsid/execve；失败把 errno 写进错误管道后 _exit(127)
父进程：读错误管道（EOF = exec 成功；有字节 = exec 失败，回收并返回错误）
        → 记录 pid/进程组 → 返回 Process
```

这样 `Spawn` 返回时**要么子进程已成功 exec，要么调用方拿到确定的错误**，不会出现
「以为起来了其实 exec 失败」的半状态。

### 2.3 Supervisor / ProcessPool 线程模型

- **Supervisor 是单线程 `ppoll` 事件循环**：所有被管进程的 stdout/stderr、超时、条件、
  配额都在同一线程处理；回调里不能阻塞。
- **ProcessPool**：有界任务队列 + N 个 worker；`block_when_full` 控制提交是阻塞还是拒绝；
  进程异常退出由「补位」逻辑重建。
- **ShmChannel 没有内核事件**：读方空读后短轮询退避（50µs）；`MessageQueue` 的异步走
  `AsyncIoBinding`（epoll），不用 `mq_notify`。

### 2.4 G2CF 帧（字节通道）

`magic "G2CF"` + `version=1` + `type` + `flags` + `payload_size` + payload + CRC32
（覆盖 version..payload）；单帧上限 `kMaxFramePayloadLimit = 64 MiB`，默认 8 MiB。
`MessageChannel` 的 `kRaw`/`kLine`/`kLengthPrefixed` 三种模式共用这一层。

## 3. 对外 API（关键接口）

### 3.1 文件与目录

```cpp
class File {
public:
    static Result<File> Open(const std::string& path, OpenFlag flags);
    static Result<File> Create(const std::string& path);
    static Result<File> Adopt(int fd);            // 只接受普通文件
    Result<std::size_t> Read(void* buffer, std::size_t bytes);
    Result<std::size_t> ReadAt(void* buffer, std::size_t bytes, std::int64_t offset);
    Result<std::size_t> Write(const void* data, std::size_t bytes);
    Result<std::size_t> WriteAll(const void* data, std::size_t bytes);
    Result<std::size_t> Writev(const iovec* iov, int count);   // 批量，最多 1024
    Result<std::size_t> Readv(const iovec* iov, int count);
    Result<std::uint64_t> CopyTo(File& dst, std::uint64_t max_bytes = 0); // sendfile
    Result<std::uint64_t> Seek(std::int64_t offset, int whence);
    Result<FileStatus> Stat();
    Result<FileStatus> Capability();              // IoCapability
    Result<void> Sync();  Result<void> Truncate(std::uint64_t size);
    Result<void> Close();
};
Result<std::string> ReadFile(const std::string& path);
Result<void> WriteFile(const std::string& path, std::string_view data);
```

`ReadDir` 不递归、`MkdirAll` 等价 `mkdir -p`、`RemoveAll` 两阶段删除（`lstat`，不跟随链接）。
所有按路径入口对内嵌 NUL 返回 `kInvalidArgument`。

### 3.2 进程

```cpp
struct ProcessOptions {
    std::vector<std::string> argv;      // 不经 shell
    std::vector<std::string> env;       // 白名单/覆盖
    std::string cwd;
    StdioMode stdio = StdioMode::kPipe; // kPipe/kInherit/kNull/kFile/kPty
    bool use_pty = false;
    std::size_t max_output_bytes = 1 << 20;
    // nice/亲和性/sched/umask/uid/gid/rlimits/OOM...
};
struct ExitStatus { bool reaped, exited, signaled, core_dumped, timed_out;
                    int exit_code, signal; std::int64_t wall_ms; };
class Process {
public:
    Result<void> Wait(std::chrono::milliseconds timeout);   // 0 立即 / <0 永久
    Result<ExitStatus> TryWait();
    Result<void> Kill(int signal);  Result<void> Terminate();  Result<void> KillTree();
    Result<ProcessInfo> Info();     bool Alive();
    MessageChannel* stdin_channel();  // stdout/stderr 同
    int native_fd() const;
};
Result<Process> Spawn(const ProcessOptions&, ...);
struct RunResult { ExitStatus status; std::string standard_output, standard_error;
                   std::size_t stdout_truncated = 0, stderr_truncated = 0; };
Result<RunResult> Run(const ProcessOptions&, ...);   // 写 stdin + 并行排空 + 超时 TERM→KILL
ProcStatsSnapshot StatsSnapshot();
void IgnoreSigPipe();
```

超时语义全模块统一：`0` 立即返回、`<0`（`kWaitForever`）永久、`>0` 最多等待并返回 `kTimeout`。

## 4. 最小用法（可编译）

### 4.1 跑一个子进程并收集输出

```cpp
#include "go2cpp/os/proc.hpp"

#include <cstdio>

using namespace go2cpp::os;

int main() {
    IgnoreSigPipe();                    // 写已关闭管道返回 EPIPE，而不是被杀
    ProcessOptions options;
    options.argv = {"/bin/sh", "-c", "echo hi; echo err >&2; exit 3"};
    auto run = Run(options);            // 默认收集 stdout/stderr，超时 TERM→KILL
    if (!run.ok()) {
        std::fprintf(stderr, "run failed\n");
        return 1;
    }
    std::printf("out=[%s] err=[%s] code=%d\n",
                run.value().standard_output.c_str(),
                run.value().standard_error.c_str(),
                run.value().status.exit_code);
    return run.value().status.exit_code == 3 ? 0 : 1;
}
```

### 4.2 管道 + 共享内存环

```cpp
#include "go2cpp/os/channel.hpp"
#include "go2cpp/os/shm.hpp"

auto pipe = go2cpp::os::Pipe::Create();       // O_CLOEXEC，两端可 Release 给子进程
if (pipe.ok()) {
    int w = pipe.value().ReleaseWrite();
    // ... 把 w 传给子进程，父进程用 ReleaseRead() 端读
}

// 共享内存 + SPSC 环（跨进程零拷贝；没有事件通知，读方短轮询）
auto shm = go2cpp::os::SharedMemory::Create("demo.shm", 1 << 20);
if (shm.ok()) {
    go2cpp::os::RingBuffer ring;
    ring.Init(shm.value().data(), shm.value().size());
    ring.Write("hello", 5);
    char buf[8];
    auto n = ring.Read(buf, sizeof(buf));      // n.value() == 5
}
```

构建：`g++ -std=c++17 -Iinclude demo_os.cpp -Lbuild -lgo2cpp_os -lgo2cpp_config -lgo2cpp_io -pthread`。

## 6. 性能数据

来源 [docs/reports/asm-os.md](../../docs/reports/asm-os.md)（2026-11-02，Ryzen 9 8945HX，
`taskset -c 6`，Release `-O2`，独立构建 `/tmp/build-os`）：

| 项 | 结果 | 相对基线 |
|---|---|---|
| 单条 `read` 1e6 次 | 459~467 ns | 原生 450~464 ns → **1.01~1.03×** |
| 单条 `write` 1e6 次 | 829~837 ns | 原生 827~838 ns → **1.00~1.01×** |
| 文件读写 vs Go `os.File` | — | **0.73~0.81×（更快）** |
| `ReadFile`/`WriteFile` 8 MiB vs Go | — | **0.30~1.05×** |
| 批量 `Writev`（1e6 条 8B，批 1024） | **46.7 ns/条** | 单条 837 ns → **17.9×** |
| 批量 `Readv` | **21.8 ns/条** | 单条 457 ns → **20.9×** |
| `WritevAll` / `ReadvAll` | 43.2 / 22.6 ns/条 | **19.4× / 20.2×** |
| `CopyTo`（sendfile）8 MiB 热 | 1237~1251 MiB/s | read+write 1004~1118 → **1.10~1.15×** |
| `CopyTo` 256 MiB 冷读 | 1043 MiB/s | 692 MiB/s → **1.51×** |
| `Process` spawn+wait（同进程 A/B） | — | **1.13~1.22×**（未达 <1.1×） |
| `SharedMemory`+`RingBuffer` 写 512 MiB | **25.5 GiB/s** | 贴单核 memcpy 上限 |
| 同上读 | **32.1 GiB/s** | — |
| `MessageQueue` Send+Receive 8B 往返 | **614k msg/s** | — |
| `MessageQueue` 批量 8 条/批 | **628k msg/s** | — |

三条诚实结论（原文）：

1. **单条文件 IO 已与原生 syscall 持平**：内联 `syscall` 把 `File::Read` 从
   46 指令/2 call/24B 栈帧降到 **38 指令/0 call/0B 栈帧**；
2. **数量级收益在架构层**：`Writev`/`Readv` 把 1e6 次 syscall 合成 977 次，17.9×/20.9×；
3. **`Process` 没到 <1.1×**：`fork` 前后固定成本仍高，剩余差距未定位到单一热点。

## 7. 边界与已知限制

1. **阻塞 M**：在 Fiber 里直接调 `File`/`Process`/`Pty` 的阻塞 API 会卡住整个 worker 线程；
   要么 `EnableAsync`（仅 pollable fd），要么放独立线程。这是本模块与 `network` 最大的区别。
2. **`File` 只接受普通文件**：`Adopt` socket/FIFO/eventfd 返回 `kIsSocket`/`kNotRegularFile`；
   普通文件也不可 poll/异步（`pollable=false`）。
3. **SIGPIPE 不自动忽略**：`Kill`/写管道前显式 `IgnoreSigPipe()`；本模块不擅自改全局信号处理。
4. **共享内存没有事件通知**：`ShmChannel` 读方短轮询（空读退避 50µs），不能当 epoll fd 用。
5. **消息队列受内核上限约束**：`/proc/sys/fs/mqueue/*`（默认 10 条 × 8192 B），大队列要用 shm。
6. **需要 root 的能力**：eBPF 监控（`os/monitor`）需要 CAP_BPF/root；普通进程拿不到。
7. **进程池的两条并发约束**：`Shutdown` 后不能再 `Submit`；`Resize` 缩容不杀正在跑的任务。
8. **测试缺口**：迁移前 `tests/os/test_os_proc_lifecycle.cpp` 等装置没有随代码迁入，
   当前树只有 file/dir/hook_conflict 三组；proc/shm/mq/pty 的回归要自己补。
9. **Windows 不支持**：fork/exec/POSIX mq/PTY 都是 POSIX 语义。

## 9. 交接注意

- **先判断「这段代码跑在 Fiber 还是普通线程」**：本模块的阻塞调用在 Fiber 里会拖住
  整个 M；需要协程语义就用 `AsyncIoBinding` 或独立线程。
- **`Run` 的 stdin 写入与输出排空是并行的**，否则子进程写满管道会死锁；改 `Run` 时别把
  输出泵改成串行。
- **fork 后子进程只做 async-signal-safe 的事**：`execve` 前不要 malloc/加锁/调 C++ 运行时；
  错误通过 `O_CLOEXEC` 错误管道回传（EOF=成功，有字节=失败）。
- **`File::Read/Write` 走内联 syscall，不经过 Hook**：不要试图用 `EnableAsync` 让普通文件
  变异步（`DetectIoCapability` 会返回 `pollable=false`）。
- **`CopyTo` 的收益有条件**：热 page cache 只有 5~15%，冷读才 1.5×；别在文档里写成无条件加速。
- **`RingBuffer` 是 SPSC**：单生产者单消费者；多生产者要自己加锁或换 `MessageQueue`。
- **未完成事项**：`Process` 的 <1.1× 目标、proc/shm/mq/pty 的测试装置迁移、eBPF 监控的
  非 root 回退方案。
