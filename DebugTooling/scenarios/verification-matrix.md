# scenarios · 验证矩阵（第 12 轮，深化③）

> 把 **34 个场景** × **15 个接口** × **测试类型** 串成一张可执行的对照表，
> 供编码阶段直接当验收清单用。
> 测试类型代号：**压**=压测（`design/07` §1）、**随**=随机测试（§2）、**场**=真实场景（§3，编号 N1–N6）、
> **微**=微基准（§4.3）、**破**=破坏性测试（§5.2）。

## 3. 发布前检查清单（Checklist）

### 3.1 功能层

- [ ] R 组 6 个只读接口全部实现，且**失败语义**与 `design/06` 一致
- [ ] 34 个场景逐条通过，且每条记录了**实际结果**（不是只写"通过"）
- [ ] dump 的 text/ini/json 三种格式对同一快照输出**字段一致**
- [ ] 缺信息呈现区分「未注册」与「无来源」
- [ ] 快照输出带「分片级一致、全局非原子」标注

### 3.2 干扰层（调试工具特有）

- [ ] 档 0→1（空观察者）差异 < 2%（**实测后校准阈值**）
- [ ] 档 0→2（真实 sink）差异 < 5%
- [ ] sink `Write` P99.9 < 5 µs、max < 20 µs
- [ ] 背压场景下发布端**零阻塞**，丢弃计数准确
- [ ] `emit_event` 微基准三档数据已记录

### 3.3 控制面（C 组）

- [ ] **默认关闭时**所有 C 接口不可用，且系统行为与未启用时一致（同基准对比）
- [ ] 每个 C 接口在**前置不满足时幂等失败**（不做任何改动）
- [ ] 迁移可回滚；插队跨 P 报错；断点只停安全点；选择器有饥饿保护
- [ ] 所有 C 组操作在 dump 输出中**标注「调试控制面已启用」**
- [ ] 插件异常**不得**穿出调度器边界

### 3.4 文档与记录

- [ ] 每个接口的**前置条件/失败语义**已写进对应头文件注释
- [ ] 「做不到的能力」六项在 CLI 帮助与文档中均有声明
- [ ] 与 gdb 的分工（gdb 看原生栈、本模块看 Fiber 逻辑栈）已写明
- [ ] 变更记录写入项目既有 AI 协作记录文件（`codex.md`）
- [ ] 性能数据写入 `docs/performance.md`，并按既有要求标注宿主/构建/参数/区间

## 4. 编码阶段的推进顺序（与 `design/06` §5 一致）

```
第 1 步  R1/R2（枚举）+ 微基准（§4.3，成本最低、最早给结论）
第 2 步  T1（序列化）+ P3（stdio/文件 sink）→ dump 可用
第 3 步  R3/R4/R6（per-G 与锁快照）→ A 类与 D1/D2 通过
第 4 步  R5（元数据）← 需先定案注入方式
第 5 步  P4（事件缓冲）+ C7 → A7/C7 通过
第 6 步  C1/C2/C3/C5（控制面，默认关闭）→ B 类通过
第 7 步  C4（断点）← 需先统计安全点
第 8 步  T2 + 时钟方案 → E2/E3
第 9 步  E4（gdb 映射导出）
第 10 步 T3（录制回放）
```

## 5. 本矩阵的自我约束

- "依赖接口"列中的 **R/C/P/T 编号**均来自 `design/06-interface-signatures.md`；
- "阻塞项"列只列**真正阻塞**的事项（未定案或未统计），不把"需要写代码"当阻塞项；
- 判据中的**量化阈值**均为建议值，必须实测校准（`design/07` §4.5 已声明）。
