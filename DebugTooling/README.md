# Go2Cpp GMP / 协程调试模块（分析与设计）

> **本目录是设计阶段的交付物：只有文档，没有代码。**
> 使用者明确要求「编码任务暂且不执行，在完成分析之后向我展示和汇报」。

## 任务背景（使用者原话要点）

针对 **GMP 模型**与**协程**特点，开发一套**调试/可视化模块**（分支开发）：

- 能查看某个 Fiber 的**任务信息**（`s_main_task` 名字、fiber 编号、函数行号、描述）；
- 能在运行中**替换**该函数；
- 能把 Fiber **跨权限切换**到其他 M；
- 能把 Fiber **插队**到指定 Fiber 之前执行；
- **可视化 Fiber**：`Go2Cpp dump scheduler [--options] ... scheduler_name`，
  例如显示 Fiber 函数名称、支持重定向到文件，**至少 15 个选项场景**；
- 输出形如 ini / json 的元信息：调度器信息、当前 Fiber 数量、全局队列、
  `G1_infos`（`cur_State` 阻塞/挂起/异常、`LocalFiberQueue` 信息、插件式 fiberid +
  函数名与描述 + 状态、可选的 Fiber 递归调用栈、可选断点信息）、`G1Processeer infos` …
- **所有操作全部开放**：包括**插件式 Debug 断点**、所有中间可变信息；
- 全运行时调度信息，可**混合 gdb** 使用（线程与调度器联合调试）；
- **锁信息**也要进入调试场景：可以在**锁争抢时决定哪个 Fiber 获得权限**。

## 硬约束（来自使用者与本项目规范）

1. **本阶段不写代码**；
2. **不熟悉代码绝不贸然开发**——所有结论必须指向具体文件与行号；
3. **不了解多场景绝不写死代码**——设计必须预留插件位，不做单点假设；
4. 项目文件只能经 `wsl bash -lc` 写入（Windows 侧是过期副本）；
5. `git` 只 `add` 明确路径，不用 `add -A` / `add .`；
6. 禁止以 PowerShell 写逻辑。

## 方法论

- **源码驱动**：每一条"项目已支持/不支持"的判断，都给出文件 + 行号；
- **能力矩阵**：把使用者的每条需求映射为「现有能力 / 缺口 / 需要的新机制」；
- **区分只读与变更**：观测（Observer）与运行时控制（替换/迁移/插队/断点）是**两套**机制，
  不能混为一谈——前者已存在，后者需要新设计且带安全约束。
