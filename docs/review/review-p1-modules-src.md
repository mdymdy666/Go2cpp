## 3. 临时探针复现记录（不改仓库，`/tmp` 编译）

探针直接链接仓内 `build-review/libgo2cpp_bento.a`，仅使用公开 API：

- **SessionControl（`sc_probe`）**
  - `[1] events=2 first=preempted peer=1 controller_field=1 (controller()=2)` → SESS-02
  - `[2] events=1 reason=lease_expired controller_field=1 (controller()=0)` → SESS-02
  - `[3] revoked_before=1 revoked_after_rejoin=0 request_after=1` → SESS-01
  - `[4] revoked_after_grant_none=0 request=1` → SESS-04
  - `[5] revoke_noncontroller=1 events=0 generation_delta=0 revoked=1` → SESS-03
- **PeerHub 明文重连（`hub_reconnect_probe`，客户端 `peer_timeout_ms=300`，服务端 3000）**
  - `[connect] client_state=connected server_active=1` → 正常
  - `[before-reconnect] server_rx=1` → 首条流送达
  - 只驱动客户端 700ms：`[after-idle] client_state=timed_out client_timeouts=1`
  - `Connect=1` 后：`[reconnect] client_state=timed_out ... server_state=connected`；服务端超时后再试：`[reconnect-2] client_state=timed_out server_state=connected` → PEB-02
- **PeerHub 加密重连（`hub_reconnect_secure_probe`，同一 PSK）**
  - 重连后：`[reconnect] client=connected server=connected server_conn=...`
  - `[after-reconnect] server_rx=1 stale=1 dup=0 client_inflight=0 client_retrans=0` → 新消息被 stale 丢弃且客户端已确认 → PEB-02（静默丢数据）
- **PeerHub 容量耗尽（`hub_peer_exhaust_probe`，`max_peers=4`，明文）**
  - `[timed-out] peers=4 active=0 timeouts=4`
  - 新 HELLO：`[after-new-hello] peers=4 rejected=1 new_joined=0` → PEB-04

## 4. 亮点

- **SessionControl 的唯一控制器不变式可靠**：所有状态变更在同一 `std::mutex` 内完成，`m_controller` 与 `kInteract` 的对应关系在 16 线程并发 + 4000 步随机操作下成立（`test_session_control` 14816 checks PASS）；`Dispatch` 明确在释放锁后调用回调（`session_control.cpp:101-109`），回调内查询 `Snapshot()` 不死锁（测试已覆盖）。
- **数据面 AEAD 的关键安全属性实现正确**：`SealAndSend` 先提交 `tx_wire_seq` 再发送，发送失败也不复用 nonce（`peer_hub.cpp:447-449`）；`OpenFrame` 先查重放窗口、只在 tag 校验通过后 `Accept` 推进窗口（`crypto.cpp:781-808`），伪造高序号无法推高窗口；数据帧只有 AEAD 通过才更新 peer 地址（`peer_hub.cpp:1180-1184`）；明文拒绝覆盖 HELLO/ACK/数据三类（1228-1234、1259-1265、1145-1151）。
- **每 peer 独立密码学状态**：独立 client/server nonce、方向密钥、`tx_wire_seq`、数据/握手重放窗口（`Peer.hpp:145-160`），握手 ACK 带 64 位重放窗口（`peer_hub.cpp:1459-1463`），HELLO/ACK 用缓存实现幂等重传（485-502、1386-1406）。
- **密码学原语可审计**：ChaCha20/Poly1305/AEAD 有 RFC 8439/7539 向量测试（`tests/bento/test_crypto.cpp:75-158`），tag 使用常量时间比较（`crypto.cpp:435-444`），`AeadOpen` 先验 tag 后解密（446-466）。
- **日志钩子设计克制**：未注入 hook 时零格式化/零分配；级别过滤、按级别/事件计数、`ResetStats` 齐全；sink 在锁外调用避免自锁（`log_hook.hpp:187-211`）；PeerHub 所有日志 message 均为字符串字面量，不打印 PSK/nonce/key/明文（全文件核对，无敏感字段拼进 `EmitLog`）。
- **代码风格与既有 Link 一致**：命名（`m_`/`k`/PascalCase）、错误注入（`std::string* error`）、Doxygen 注释、线程模型说明齐全；`peer_hub.cpp` 对“为什么这样路由/为什么控制帧要带 conn_id”等关键决策有到位注释（463-465、604-607）。

## 5. 维度结论

| 维度 | 结论 |
|---|---|
| 正确性 | SessionControl 主不变式成立，但事件 `controller` 字段、Revoke 持久性、`kNone` 语义有缺陷；PeerHub 的 `Connect()` 重连状态不一致（明文不可恢复/加密静默丢数据），是本次最需要优先修的正确性问题。 |
| 并发 | SessionControl 锁外回调正确；`on_change` 为公开 `std::function`，运行期替换与并发回调存在数据竞争（头文件已注明“初始化阶段设置”）。PeerHub 回调全部在 Hub 锁内同步执行，回调内删 peer/关 Hub 会 UAF/迭代器失效（PEB-01）；`RunOnce` 持锁 `poll` 会阻塞并发 `Send*` 最长 `timeout_ms`。 |
| 资源 | 无 fd 泄漏（`Close` 关闭 socket，通道/内存有上限）；但 `kTimedOut` peer 永久占用 `max_peers`（PEB-04），密钥材料未清零（PEB-07），`SealAndSend` 每帧分配 `std::vector`（热路径可优化）。 |
| 错误处理 | `Open/AddPeer` 错误串清晰；但日志原因用字符串比较（PEB-10），握手/超时事件分类不准；`Tick` 注入时钟与内部 `NowMs()` 混用（SESS-05）。 |
| 安全 | 数据面（AEAD、重放窗口、明文拒绝、认证后迁移）实现正确；**握手面缺 HELLO 重放窗口/nonce 历史**（PEB-03，且同仓 Link 已有可复用实现）；密钥清零与热切换语义需补（PEB-07/09）；日志未泄露密钥（亮点）。 |
| 风格/可维护性 | 注释质量总体高；crypto.hpp 线格式文档与实际 16B 头不一致（DOC-01）；少量死参数/死变量/魔法字符串（PEB-11、SESS-03）。 |
