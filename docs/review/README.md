## 状态图例

- `待读`：还没开始看
- `已答`：已给出结论与证据，用户未追问
- `待确认`：结论依赖未验证的假设/运行结果
- `已修` / `未修`：对照 HEAD 的缺陷状态（不要与「已答」混用）

## 一条问题的写法

```markdown
### Q-003 <一句话问题>
- 提问：（用户原话，可截断）
- 结论：（先给判断）
- 证据：`文件:行号` + 代码片段（3~8 行）
- 风险/建议：
- 状态：已答 / 待确认
```

## 维护规则

1. **只追加**：历史结论不删；结论变化时新增「修订」条目并注明日期。
2. **证据优先**：没有 `文件:行号` 的结论标 `待确认`，不写成定论。
3. **区分基线**：HEAD 结论与工作树中间态分开写。
4. 稳定结论可回填 `docs/code-review-guide.md` 的「已知坑」；临时发现继续放 `/tmp/review_findings.md`。
