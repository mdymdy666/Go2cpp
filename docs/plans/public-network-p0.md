## 一、为什么是「公网」而不是「内网」

| 维度 | 内网（当前基准） | **公网（真实场景）** |
|---|---|---|
| 丢包 | ~0% | **1–20%**（移动网络） |
| RTT | <1ms | **20–300ms**（跨洲 200ms+） |
| 带宽 | 充足 | **波动大**（2G/4G/5G/WiFi 切换） |
| NAT | 无 | **多层 NAT / 对称 NAT** |
| 连接稳定性 | 稳定 | **频繁断线/切换网络**（地铁、电梯） |

**结论**：**内网基准（当前做的）只证明「代码不慢」**；**公网证明「产品能用」**。

## 二、参考框架（**必须读源码/架构，不是看博客**）

### 2.1 WebRTC（**公网实时传输的工业标准**）

| 子系统 | 关键机制 | 我们要学的 |
|---|---|---|
| **拥塞控制** | `GCC`（Google Congestion Control）：延迟梯度 + 丢包率 | **带宽估计**（不是固定速率） |
| **Pacing** | `PacedSender`：按 5ms 间隔发包（**避免突发**） | **平滑发送**（怕 burst 打爆队列） |
| **抗丢包** | `NACK`（重传）+ `FEC`（前向纠错）+ `ULPFEC` | **重传 vs 冗余**的取舍 |
| **Jitter Buffer** | 自适应深度（**根据网络抖动调整**） | **抖动缓冲**（音视频必需） |
| **ICE** | `STUN`/`TURN`/`ICE`（NAT 穿透） | **P2P 连接建立** |
| **连接迁移** | `ICE restart`（**WiFi→4G 不断连**） | **网络切换不断线** |
| **多路复用** | `BUNDLE`（所有流走一个 5 元组） | **减少连接数** |
| **拥塞算法** | `GoogCC` / `BBR`（WebRTC 也支持） | **BBR vs 丢包驱动** |

**源码位置**（`webrtc/modules/congestion_controller/`、`webrtc/modules/pacing/`、`webrtc/modules/rtp_rtcp/`）。

### 2.2 Unity / 游戏框架（**同步与预测**）

| 机制 | 说明 | 我们要学的 |
|---|---|---|
| **Snapshot Interpolation** | 服务器发快照，客户端**插值**（不是每帧同步） | **降低带宽**（10–20Hz 快照足够） |
| **Client-side Prediction** | 客户端**本地先执行**，服务器纠偏 | **掩盖 RTT** |
| **Lag Compensation** | 服务器**回溯**到「客户端开火时刻」判定命中 | **公平性** |
| **Delta Compression** | 只发**变化的字段** | **带宽 ↓** |
| **Reliability Layers** | 关键消息**可靠**，状态**不可靠**（UDP） | **混合可靠性** |
| **Netcode for GameObjects** | Unity 官方的传输层抽象 | **传输层可替换** |

### 2.3 具身智能「快慢脑」（**分层控制**）

| 层 | 职责 | 频率 |
|---|---|---|
| **快脑**（反射/小脑） | 实时控制、避障、平衡 | **100–1000 Hz** |
| **慢脑**（大脑） | 规划、决策、语义理解 | **1–10 Hz** |

**对网络架构的启示**：
- **快慢分层** → **关键控制流走低延迟通道**（不排在大包后面）；
- **慢脑可容忍延迟** → **大包（日志/模型）走独立通道**；
- **QoS 分级**：**不同优先级走不同队列/不同拥塞策略**。

## 三、Go2Cpp 的现状（对比上面的差距）

| 能力 | 现状 | 差距 |
|---|---|---|
| **拥塞控制** | 无（固定速率/无速率） | 🚩 **最大差距** |
| **Pacing** | 无（直接写 socket） | 🚩 突发打爆队列 |
| **抗丢包** | 无（TCP 重传 / UDP 不管） | 🚩 弱网不可用 |
| **Jitter Buffer** | 无 | 🚩 音视频不可用 |
| **NAT 穿透** | 有 `tunnel`（**单跳**，不是 P2P） | 🚩 无 ICE |
| **连接迁移** | 有 `WS Resume`（**断线重连**，非迁移） | 🚩 切换要重连 |
| **多路复用** | 有 `mux`（HTTP/2 风格） | ✅ 已有 |
| **QoS 分级** | 无 | 🚩 关键流会被大包阻塞 |

## 六、与「可裁剪性」的关系

> **这些公网能力应该做成「可选模块」**（`go2cpp_pacing`/`go2cpp_bwe`/`go2cpp_nack`），
> **不是塞进 `go2cpp_network`**——**否则内网/简单场景被迫拖入公网复杂度**。
>
> **符合 L0–L4 分层**：`pacing/bwe` 是 **L3**（依赖 IO），**不是 L2**。
