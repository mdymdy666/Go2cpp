# 回复格式规范（标准）

> 生效：2026-11-03。适用于本对话与所有自动任务的汇报。
> 来源：用户明确要求「回复方式改为标准的，并持久化」；此前 16:16 自动任务把「已完成/下一步」挤成一段、内联代码堆在句子里，被指出不合格。

## 1. 结构（固定五段，无内容可省略）

```markdown
## 结论
一句话说清本轮结果（成/败/部分，带关键数字）。

## 完成内容
### 1. <事项名>
- 一行短句说明做了什么；文件与命令放到下一段「证据」里。

### 2. <事项名>
- 同上。

## 证据
表格或代码块（命令、输出、行号）。**不把代码塞进句子中间**。

## 下一步
1. 可执行动作（谁、做什么、验收点）
2. ...

## 待确认（可选）
- 只有需要我决策时才写；否则省略。
```

## 2. 硬性规则

| 规则 | 说明 |
|---|---|
| 首行结论 | 必须先给结果，不铺垫 |
| 分段 | 「已完成 / 下一步」不得挤在同一段 |
| 代码位置 | 路径、命令、输出放**证据**段的代码块或表格；句子内最多一个反引号词 |
| 表格优先 | 多组数据用表格，不用长句罗列 |
| 无 emoji | 不用 emoji 代替标题 |
| 无空话 | 不出现「做/快/好/执行/继续推进」这类无内容确认 |
| 每轮收尾 | 「下一步」必须是可执行动作或具体问题 |

## 3. 反例（禁止）

- ❌ 一整段：`已完成：xxx（373 行，FR-01..FR-10 + ...）已提交推送 c9814bb，迁移后 ./build.sh 7 个二进制 rc=0。下一步：C2 ...`
- ❌ 句子中间夹五六个内联 `code`，读者分不清哪些是命令、哪些是结论。
- ❌ 只有「已完成 / 下一步」两行，没有证据与下一步的具体动作。

## 4. 正例

```markdown
## 结论
C2 user 服务交付，6 条 curl 全过，重复注册 409 正确。

## 完成内容
### 1. 存储层
- 新增 SQLite 存储封装，建 users/follows 表，WAL 模式。

### 2. 鉴权
- 密码 SHA-256+盐；token = base64url(payload) + HMAC-SHA256。

## 证据
| 用例 | 结果 |
|---|---|
| 注册 | 200 |
| 重复注册 | 409 |
| 错密码 | 401 |

## 下一步
1. 主控复跑 `scripts/accept_user.sh`；
2. 通过后提交并进入 C3 video 服务。

## 待确认
- 无。
```

## 5. 执行方式

- 本文件在 `docs/plans/reply-format.md`，每轮自动任务开始前读一次；
- 若发现某轮汇报违反，下一轮必须按本规范纠正，并在 `docs/plans/autopilot-progress.md` 记一行。
