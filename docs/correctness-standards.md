# 正确性标准（Go2Cpp）

> 与 `docs/engineering-standards.md`（工程/工业级）、`~/.dsh/AGENTS.md`（性能）配套。

## 一、正确性门槛（每个模块必须全过）

| # | 门槛 | 证据 |
|---|---|---|
| 1 | **与基线逐字节一致**（序列化/编解码/协议/哈希） | 对拍输出（SHA-256/逐字节 diff） |
| 2 | **压测 ≥1e7 操作，0 错误** | checks/failures 原始输出（含校验和/序号/ID 唯一性） |
| 3 | **ASan/UBSan 零错误零泄漏** | 报告（无 leak/overflow/UB） |
| 4 | **随机测试 ≥1000 轮** | 种子 + 结果 |
| 5 | **真实场景 ≥5 个**（覆盖全部功能） | 每场景的用例 + 断言 |
| 6 | **边界全测**：空/超长/畸形/超时/取消/关闭/并发竞争 | 每类一个用例 |

## 二、禁止

```
❌ 只做冒烟测试（"能跑"不等于"对"）
❌ "没崩溃就算对"
❌ "概率性通过"当作正确（必须 1e10 次或理论证明）
❌ 跳过 ASan（内存错误往往潜伏）
❌ 只测 happy path（不测畸形/边界）
```

## 三、性能与正确性的关系

- **性能优化不得改变语义**：优化前后必须逐字节一致 + 命中率/结果不变；
- **并发优化必须有压测**：每个改动过的原语独立压测（≥1e7）+ ASan/TSan；
- **缓存优化必须命中率一致**：35 组场景逐位一致（0.000000 偏差）。

## 五、交付检查

```
□ 逐字节对拍证据（或 SHA-256）
□ 压测 ≥1e7 + checks/failures
□ ASan/UBSan 干净
□ 随机 ≥1000 轮
□ 真实场景 ≥5
□ 边界 7 类全测
□ 并发改动有独立压测
□ 优化前后语义一致
```
