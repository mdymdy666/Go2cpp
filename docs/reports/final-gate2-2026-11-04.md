## 真失败清单

### 1. ASan `go2cpp_storage_orm_test` — 真缺陷（阻塞）
`src/storage/orm.cpp:246` 的 `std::string fallback` 在块作用域结束后析构，但 `default_sql`（string_view
参数）仍指向它，`orm.cpp:266` 的 `sql += default_sql` 读取已释放栈内存 → ASan
`stack-use-after-scope`（READ size 2）。Release 下测试通过属 SSO 残留巧合，UB 真实存在。
触发条件：`AddColumnSql` 且 `not_null`、无默认值。修复方向：`fallback` 提升到函数作用域，
或用 `std::string` 持有后再赋值。

### 2. ctest `tunnel` — 性能阈值失败（非功能）
`test_tunnel.cpp:884 ratio < 4.0`：直连 p50=0.295ms / 隧道 1.229ms = **4.17x**。
单独复跑 3 次：4.49x / 5.02x（并行负载下）。功能 169/170 检查通过；上一轮（547c621）为 4.95x。
根因：回环直连基线极低（0.3ms）时隧道固定开销（两端 RelayPipe 线程 + 2 次 connect）被放大，
阈值对本机不成立，或需预热/取更稳基线。

### 3. ctest `go2cpp_os_tcp_io_monitor_root` — 环境依赖
eBPF first-event race `GO2CPP_CHECK(lost_rounds <= 1)` 实测 2/30 轮丢样（round 3 丢 11、round 19 丢 10）。
CI 主构建默认 `-DGO2CPP_BUILD_OS_MONITOR_TESTS=OFF` 排除该组；WSL eBPF 并发首事件采样限制。

### 4. TSan `fiber.cpp` 报告 — 已知 P3 误报候选（不阻塞）
84 处 data race 全部落在 `fiber.cpp` 2453/2161/2442/2315/2329（`thread_local t_current_growable_stack`
与 fiber 栈切换），与 `docs/reports/sanitizer-2026-11-04.md` §4.2 判定一致：M:N 调度 fiber 跨 OS 线程
迁移 + `__tsan_switch_to_fiber` 注解不完整导致；除 fiber 外 0 处竞态。

## 结论

**有阻塞**：ASan 暴露真实内存安全缺陷（`AddColumnSql` 悬垂 `string_view`），不符合工业级放行。
其余：告警 0、构建一致、tunnel 源码一致；tunnel ratio 与 eBPF 丢样属阈值/环境噪声；
TSan 无新增竞态（fiber TLS 为既有误报候选）。修复 orm.cpp 悬垂视图并单独复跑 ASan 后可再审。
