# RPC 端到端延迟与吞吐实测（2026-11-05）

> **背景**：`docs/plans/doc-perf-sync.md` §二 曾把 rpc「p50 149 µs / 177k/s」列为「无出处，禁止引用」。
> 本文用仓库内现有测试实跑一次，给出可复核的 source of truth。**只跑现成测试，不改代码**。
>
> **结论**：p50 = **114.4 µs**，单连接串行吞吐 = **7,350/s**，8 客户端 × 32 线程并发吞吐 = **212,701/s**。
> 历史「149 µs」比实测高 30%，「177k/s」既不是串行吞吐（差 24 倍）也不等于并发吞吐（212.7k），
> **无法复现 → 继续禁止引用**；台账记为 M23（`实测`）。

## 4. 结果汇总与「149 µs / 177k/s」核对

| 指标 | 实测（本报告） | 历史宣称 | 判定 |
|---|---|---|---|
| p50（单连接串行，1e6 次） | **114.4 µs** | 149 µs | **不复现**（历史高 30%） |
| p90 / p99 / p999 / max | 217.6 / 305.1 / 3566.3 / 16411.6 µs | — | 本次新增 |
| mean | 136.0 µs | — | — |
| 串行吞吐（1e6 / wall 136.06 s） | **7,350/s** | 177k/s | **不复现**（差 24.1×） |
| 并发吞吐（8 clients × 32 threads，1e5 次，0 失败） | **212,701/s**（wall 470.1 ms） | 177k/s | 接近但不同口径（历史未记并发度） |

判读：

1. **p50 114.4 µs 与 mean 136.0 µs 自洽**（长尾把均值拉高）：`1e6 × 136.0 µs = 136 s`，正好等于 wall 136.06 s。
2. **串行吞吐 7,350/s 是「一次调用等一次响应」的上限**，与 p50 不同量级——把它写成 177k/s 只能是并发口径或错误。
3. **并发口径实测 212,701/s**（8 客户端 × 32 线程），已高于 177k/s；历史 177k/s 未记并发度/连接数，**无法对齐，按无出处处理**。
4. 长尾 `p999 3.57 ms / max 16.4 ms` 来自宿主调度与 TCP 环回突发，本机 loadavg 1.5–2.7 时单次运行；改善需绑核 + 多轮中位，留作下次复跑。
