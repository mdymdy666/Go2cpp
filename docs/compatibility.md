# Compatibility Matrix

This project is an independently usable C++17 library. It implements a
bounded, explicitly documented subset of Go runtime behavior; it is not a Go
parser, compiler, ABI, garbage collector, or claim of language equivalence.

| Go facility | Implemented subset | Deliberate difference or precondition | Verification |
|---|---|---|---|
| G/M/P scheduling | `Task` is G, worker `Machine` is M, and a configured `Processor` is P. Each G has one owner scheduler, one execution claim, local/global FIFO queues, bounded stealing, park/unpark pending-wake handoff, cancellation and shutdown. | Scheduling is cooperative at explicit Fiber/yield/park boundaries. A native call that is not intercepted occupies its M. No asynchronous compiler preemption, segmented Go stack, exact Go fairness, or M>P blocking-region handoff. | `test_scheduler`, `test_dynamic_scheduler`, smoke stress and `dynamic_gmp_demo` |
| G completion and lifetime | A returning callable, handled/unhandled panic, or cancellation reaches a terminal state. Shutdown wakes parked Gs and joins workers; a completed Fiber stack and callable are released after its trampoline returns, even if a user still holds the `Task`. Direct backend `Task::run()` calls have a separate execution claim. | A non-cooperative callable that never returns can keep shutdown/join waiting, like an unjoined `std::thread`. An unstarted cancelled task may retain its callable until its stale queue node is reclaimed. The `Scheduler`/`IOManager` owner must outlive its worker threads; destroying it from one of its own Gs fails fast rather than risking use-after-free. The runtime never force-discards a suspended C++ stack. | Fiber lifetime, shutdown, cancelled-queue capture release, reentrant-destructor and watchdog tests |
| Dynamic M | `min_workers`, bounded `max_workers` (clamped to P), backlog-driven growth, idle retirement, dead-worker reaping, P ownership accounting and soft task-class affinity counters. | M count cannot exceed P because blocked-region release is not implemented. Affinity is a bounded preference, not a cache guarantee; no CPU pinning. | Six growth/shrink/regrow waves, P-cap, concurrent snapshots and affinity tests |
| Fiber | Stackful Boost.Context `fcontext` backend with protected stack, migration between M threads, local errno preservation, explicit cancellation-and-join destruction, and ASan/TSan switch hooks. | Boost.Context is an implementation dependency; Memcheck is run on the binaries but no explicit Valgrind stack-registration ABI is promised. User code must not retain ordinary `thread_local` state across migration. Resume calls are serialized; destroying an uncooperative Fiber waits. | `test_fiber`, ASan/TSan/Valgrind fiber runs |
| Socket/FD hooks | Linux shared interposer is enabled by default. `socket`/`socketpair`, `connect`, `accept*`, read/recv, write/send, close, dup*, fcntl/ioctl, getsockopt/setsockopt and sleep are wrapped with original libc calls; managed potentially blocking operations add epoll readiness. Readiness is published before deadline timers; outcomes are one-shot and FD generations invalidate close/reuse. Ordinary threads use original blocking calls or bounded raw-poll fallback. | This is a bounded socket syscall surface: `MSG_WAITALL` returns `ENOTSUP` in a managed Fiber because byte-accumulation is not emulated; ordinary threads are forwarded to libc, but a socket previously adopted by the runtime remains kernel-nonblocking, so full blocking `MSG_WAITALL` semantics are not promised. Managed `MSG_OOB` receives return `ENOTSUP` because `EPOLLPRI` is outside the subset; `recvmmsg`/`sendmmsg`, `sendfile`/`splice`, `poll`/`select`/`ppoll`, signals with operation-specific restart semantics, unknown variadic fcntl/ioctl commands, fork/exec inheritance and non-Linux platforms are explicit boundaries. Direct raw syscalls that bypass the interposer are outside FD-generation tracking. `bind_io_manager` must not outlive or cross Fiber migration. Metadata allocation failure leaves the successful fd usable and is adopted lazily. Disabling hooks stops Fiber epoll admission; an already-adopted socket may still use native poll fallback. Static builds require `GO2CPP_BUILD_HOOK=OFF`; use explicit wrapper APIs/IOManager then. | `test_io`, `test_hook`, readiness/timeout races, close/reuse, native fallback and `io_hook_demo` |
| `context` roots and cancellation | `Background`, `TODO`, `WithCancel`, `WithCancelCause`, parent-to-child propagation, idempotent cancellation, `Done` callbacks/waiters, `Canceled`/`DeadlineExceeded`, optional cause, steady deadlines, timeout and immutable typed/string values. The cancellation pass marks the whole subtree before invoking callbacks, so a callback may safely wait on a descendant. Managed G waits park their Fiber. | No `WithoutCancel` helper in 0.x. Roots ignore direct cancellation, and their `Done()` is a non-null permanently pending `DoneSignal` rather than Go's nil channel. A null parent is mapped to `Background()` for a non-throwing C++ API (Go would panic). Context values are immutable C++ `std::any` values; typed key identity is not a Go interface value. | Context tree, deep cancellation, fake clock, callback race and managed Done tests |
| defer | Explicit `Frame` captures callback arguments at registration, runs LIFO on normal finish and panic unwind, allows defers added while processing. | A translator must create frame boundaries; the C++ compiler does not inject them. | Nested/LIFO, argument capture and normal/panic tests |
| panic/recover | Per-Fiber `ExecutionContext`, nested frame unwind, recover only from the active directly executing defer, re-panic replacement, `panic(nil)` marker, unhandled observer and cross-G isolation. | Runtime control flow never uses C++ throw, promise, `longjmp` or `setjmp`; an accidental user C++ throw is translated at the outer body boundary. `panic()` records the panic but does not rewrite ordinary C++ control flow; translated code must return through its frame boundary. With no unhandled-panic handler, `run()` reports failure and the scheduler terminates the G without a Go-style process abort; applications that need fatal behavior must install a handler. C++ cannot enforce every Go lexical direct-defer rule, and a throw from a `Frame` destructor is outside that Frame's recover boundary. | Panic/defer and Fiber migration tests |
| error | Immutable shared error values, null-as-nil, wrapping, `Unwrap`, iterative cycle-safe `Is`/`As`, `Join` and context/channel conversion. A singleton `Join` retains a `JoinError` wrapper, matching Go's single-element `errors.Join` shape. | No Go interface/typed-nil ABI. `Wrap(nullptr, ...)` returns null rather than constructing Go's non-null `%w`-with-nil wrapper. Custom ownership/message graphs must be acyclic; errors are never implicitly panics. | Deep chain, identity/type and cycle tests |
| channels | Typed capacity 0/1/N channels, FIFO buffered storage, multiple producers/consumers, blocking send/receive, close wake-up, zero-value receive after close, cancellation/deadline, directional views, select/default/timeout and unbuffered select rendezvous. Managed G operations park rather than block their M. | Nil channel is an explicit `kNil` status instead of an infinite block; `OrPanic` helpers upgrade closed-channel results but leave nil-channel status explicit. Empty `Select({})` or an inert case returns an invalid result instead of blocking forever. Send-after-close returns status; `SendOrPanic` opts into panic. A `Channel` object must not be destroyed while raw member calls or waiters are active; `SelectCase` captures a `ChannelPtr` and keeps it alive. Type-erased select probes require copyable elements, and select transfer/custom probe callbacks require non-throwing operations because there is no rollback contract after a wait node is claimed. Select has API builders rather than Go syntax and custom polling cases have bounded wake latency. | Channel FIFO/close/select, managed P=1, cancellation and stress tests |
| coroutine synchronization | `Fiber`, scheduler-aware FIFO `sync::Mutex`, `ConditionVariable`, reusable `WaitGroup`, timeout/cancellation and explicit unmanaged-thread immediate/failure behavior. A zero/negative `LockFor` gets one immediate try-lock attempt. | Unmanaged contended mutex operations return false (or `lock()` throws `logic_error`) instead of silently blocking an arbitrary OS thread. An already-expired `ConditionVariable::WaitFor` returns before publishing a waiter, unlike a full `std::condition_variable` unlock/relock cycle. Objects must outlive waiters; mutex ownership is deliberately Go-style and not thread-owned. | `test_sync`, P=1 waits, cancellation/shutdown and `fiber_sync_demo` |

The public result/status APIs expose unsupported states instead of silently
pretending to be Go. See `docs/design.md`, `docs/scheduler.md` and
`docs/dependencies.md` for ownership and replacement details.

Raw socket APIs such as direct `syscall(2)`, `io_uring`, `close_range` and
glibc no-cancel entry points bypass the interposer; they may block their M and
are outside FD-generation tracking and managed Fiber wake-up semantics.
