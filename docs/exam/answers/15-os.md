## Q01

**答**：PTY 模式只创建一个从端，三条流共享它（三个 fd 字段值相同，不是 dup 出来的三个）。父进程先用 `ReleaseSlave()` 把 fd 所有权从 `Pty` 对象取走，再 `close` 一次；否则 `Pty` 析构会再关一次。单线程重复 close 只是 `EBADF`，看着无害；并发 `Spawn` 时是 fd-reuse 竞态：第一次 close 释放的编号可能立刻被另一线程的 `posix_openpt/open` 复用，多余 close 命中的是**别人的** fd（表现为 master 读取 EBADF 或通道 closed）。父侧读 master 时，从端全关得到 `EIO`（不是 `read==0`），`FdChannel::Pull` 映射成关闭/EOF，否则会把正常退出当 I/O 错误。这条路径没有回归测试（注释引用的 `tests/os/test_os_pty.cpp` 不存在）。

**代码证据**：

## Q02

**答**：`writev` 允许只写前几个 iovec 的一部分就返回，下一次必须从「写到哪里」继续；`WritevAll` 快路径一次写满不分配，慢路径才复制 iovec（`std::vector<iovec> rest`）并用 `AdvanceIov` 推进：整段消耗则下标前进、部分消耗则 `iov_base` 前移 + `iov_len` 减小、全部消耗返回 `iovcnt`。重发必须用推进后的数组，否则重复已写段（数据重复）或跳过整段（丢尾部）。`iovcnt` 必须 1..1024（`kMaxIov`，超过返回 EINVAL，不能截断成 1024 偷写）。`ReadvAll` 在 EOF 返回**已读字节数**（可能小于 want），一开始 EOF 返回 0；全零 iovec 合法返回 0；慢路径 `bad_alloc` 返回已写字节并置 ENOMEM（ReadvAll 返回 -1），不能假装成功。

## Q03

**答**：等待谓词不是「队列非空」一条，而是「队列非空 **且** 本 worker 的 index 仍在新目标内（外加 stopping）」。缩容不立即杀线程：只降低 `target_workers`，worker 下次醒来且队列空时自行退出；期间 `index >= target` 的线程仍在等待。`notify_one` 可能唤醒一个「将被裁」的线程，它检查谓词失败继续睡；新任务留在队列里没有有资格的线程被唤醒 → `SubmitAndWait` 偶发超时。所以 `notify_all` 是**正确性要求**（惊群换正确），不是性能选择。`Resize` 补位必须逐槽检查 `threads[slot].joinable()`，不能只看 `alive_workers`（含即将退出者）。

## Q04

**答**：显式传 `&offset` 时 `sendfile` 只更新 `offset` 变量，**不动** `in_fd` 的偏移；所以循环结束后必须 `Seek(offset, SEEK_SET)`，让 `CopyTo` 语义与连续 `Read` 一致。单次 `sendfile` 限制 1 MiB，避免一次卡太久。回退条件：`result == 0` 是 EOF 不是错误；`result < 0` 且 `total == 0` 且 errno ∈ {EINVAL, ENOSYS, EXDEV, EOPNOTSUPP, ENOTSUP} 才允许 fallback；已经拷过字节（`total > 0`）后任何错误都直接返回 `kIoFailed` + `*copied = total`，**不回退**（混用两条路径会让已拷贝量无法推理）。`max_bytes` 是硬上限；空文件返回 copied=0 且成功；坏句柄返回 EBADF 并把 copied 归零。`sendfile` 绕过用户态，不能用于加密/改写数据。

## Q05

**答**：`fork` 在多线程进程里只复制调用线程；子进程若调用任何可能拿锁/分配内存的函数，可能死锁在「锁持有者已不存在」的状态，所以子进程只调 `SYS_*` 裸 syscall（fcntl/dup2/dup3/close_range/setsid/chdir/umask/setrlimit/setpriority/sched_*），不 malloc、不碰 `std::mutex`、不跑析构。错误回传协议：父建 `O_CLOEXEC` 管道 → fork → 子 exec；exec 成功内核关写端，父读到 0 字节 EOF；失败子写 `int errno` 再 `_exit_group(127)`，父据此返回 `kExecFailed` 并 `waitpid` 回收。fd 编号：error fd 若落在 0..2（父 stdio 关闭时 pipe2 会复用）先 `F_DUPFD_CLOEXEC` 到 `>=10`；三条源 fd 若 <=2 也先搬到 `>=10`，否则 `dup2` 会互相覆盖。error fd 最终固定到 3，`close_range(4, ~0u, 0)` 从 4 开始，不会误关 3。`setrlimit` 在 exec 前逐条设置，失败通过 error pipe 回传。
