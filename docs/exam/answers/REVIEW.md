## 二、埋点说明（本轮埋点失效，与答卷无关）

埋点做法是把某条 `文件:行号` **偏移 +3 行**。实测发现 +3 行大多仍落在**同一段注释或同一函数体内**，
内容与题意仍相关，因此「引用了偏移后的行号」不构成「没读代码」的证据：

- `01 Q09` 引用 `scheduler.cpp:1916-1918`（真 1913），1916–1918 仍是「两个 claim 必须一起翻转」这段注释；
- `04 Q03` 引用 `leveldb_kv.cpp:510-512`（真 509），整段都是 `Close()` 释放逻辑；
- `17 Q02` 引用 `writer.hpp:484-486`（真 480），整段都是 `Reset()` 实现体。

**下一轮重出题时**：偏移量提到 ±50～300 行，或直接换到同文件的另一个函数，才有区分度。

## 三、答得最好的几处（可作范本）

1. **01-Q01**：把「122 ns」拆成 6 个成立条件（8–11 核 / 4P4M / 单生产者 / 空任务体 /
   `collect_metrics=false` / `terminal_collect_interval=256`），并指出它与 submit 口径的 326.7 不可相减。
   这是对「文档数字不可信」的正确处理：不给结论，给条件。
2. **01-Q03**：2 KB 初始栈 = 请求量 → 页对齐后 4096 → 8 MiB VA 预留（PROT_NONE + MAP_NORESERVE）；
   并指出真正的容量上限是 `vm.max_map_count`，不是内存。
3. **01-Q09**：`execution_claim` 与 `run_claim` 少翻一个位 → G 永久停在 `kRunning`、shutdown 等不到终态。
4. **07-Q01**：STUN 的 Test II→III→IV 顺序不可颠倒，提前执行会把 Symmetric 误判成 Full Cone。
5. **17-Q02**：`Writer` 析构 `= default` 不碰底层，忘记 `Flush()` 等于丢数据；并指出与 Go 的差异
   （Go 遇短写直接 `ErrShortWrite`，本实现循环写完）。

## 四、若要继续深化，这些点值得看（**不是必答，是下一步的阅读/实验方向**）

### 01 concurrency
- submit 单段口径（历史 326.7）怎么单独测：读 `src/concurrency/scheduler.cpp:6041` 附近的 rdtsc 埋点
- `runnext` 单槽的饿死条件：让 A 持续 yield、B park→wake，看 B 是否被挤进 256 槽环
- `FastChannel` 与 `Channel` 同负载差别（`fast_channel.hpp` 头注释写明「实验版，不入库」的原因）
- 两条 O(n²)（shutdown、WaitNode）的曲线长什么样

### 02 network
- epoll ET 下「读一半就停」为什么会静默丢事件（对比 LT）
- HTTP/1.1 pipeline 的真实数字：`pipeline=16` 单连接，`docs/reports/asm-http-e2e.md:18` 是唯一出处
- TLS 写路径的 SIGPIPE 快路径为什么能省掉绝大多数 `sigprocmask`
- HTTP/2 stream 状态机的半关闭语义、HPACK 动态表顺序依赖

### 03 bento
- FEC 的拐点：什么丢包率下 FEC 比重传划算
- BBR 与 CUBIC 在「有丢包但非拥塞」链路上的判据差异
- 0-RTT 的重放窗口靠什么挡（PSK + 时间戳 + 去重表）
- Link 收发分离为什么让 p99 从毫秒级掉到微秒级（`recursive_mutex` 罩住接收循环的代价）

### 14 tunnel
- 12 字节头每个字段各解决什么；控制/数据连接为什么必须分离
- PSK 挑战应答全流程（token → sha256 → 32B PSK），以及为什么不用静态密钥
- drain/GOAWAY 期间在途流怎么收尾
