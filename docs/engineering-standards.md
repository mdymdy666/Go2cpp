# 工程标准（Go2Cpp）

> 本文件是项目级强制规范。与 `docs/reports/asm-*.md`（性能审查）配合使用。

## 一、对标工业级实现（强制）

**所有实现必须对标工业级实现**——不是「能跑就行」，而是「和这个领域最强的库比」。

### 1.1 实现前：先调研

- 每个模块动工前，**先检索同领域工业库**（见 §四参考清单）；
- 记录：它怎么做（架构/算法/数据结构）、性能数据、边界处理；
- **能移植就移植**（不许凭印象说「没有成熟方案」）。

### 1.2 实现后：必须对比

每个大模块完成后，**必须产出对比矩阵**（写进 `docs/reports/vs-<module>.md`）：

| 维度 | Go2Cpp | 工业库（名字/版本） | 结论 |
|---|---|---|---|
| **性能**（吞吐/延迟/内存） | 实测数字 | 官方/论文数据 | 几倍/持平/领先 |
| **功能**（覆盖度） | 支持哪些 | 支持哪些 | 缺什么 |
| **边界**（异常/极限） | 怎么处理 | 怎么处理 | 差在哪 |
| **API**（易用性） | 签名/语义 | 签名/语义 | 是否对齐 |
| **代码量**（简洁度） | 行数 | 行数 | 是否更简单 |

**禁止**：只写「我们很快」而不给工业库对照数字。

## 二、要求简单（强制）

**简洁 > 复杂**。工业级不等于「代码多」，而是「用最简单的方式达到最强」。

### 2.1 简洁准则

- **单文件/单职责**：一个模块一个 .hpp + 一个 .cpp；
- **能用标准库就不自造**（`std::` 优先，除非有明确性能理由）；
- **接口最小化**（YAGNI）——只暴露调用方需要的；
- **无过度设计**：不预先抽象「将来可能用」的东西；
- **无炫技**：不用模板元编程/宏魔法，除非收益明确；
- **注释写「为什么」不写「是什么」**。

### 2.2 反例（不许出现）

```
❌ 500 行的「通用」工厂，实际只用了 1 个实现
❌ 为了「可扩展」引入 3 层虚接口
❌ 用 template 元编程算一个编译期常量
❌ 每个类都套 shared_ptr + pimpl（无必要）
```

### 2.3 度量

- **每个模块 ≤ 2000 行**（超过要拆分或说明理由）；
- **每个公共接口 ≤ 15 个方法**（超过要反思）；
- **编译时间**：单模块 ≤ 5 秒（超过要查模板/头文件膨胀）。

## 三、尽量全面强（强制）

- **功能覆盖**：工业库有的核心功能，我们至少覆盖 80%（缺的写清理由）；
- **性能**：数据面 ≥ 工业库的 80%（并发原语 ≥ Go 的 90%）；
- **边界**：异常/超时/取消/背压/断开——每个都要处理（不许「假设不会发生」）；
- **测试**：每个模块 ≥ 5 真实场景 + 压测 ≥1e7 + ASan/UBSan。

## 四、工业库参考清单（按模块）

| 模块 | 工业库 | 对比重点 |
|---|---|---|
| **并发（Fiber/Scheduler）** | Go runtime、coost、libco、folly::fibers | 切换 ns / 调度 ns / 内存 |
| **Channel** | Go channel、muduo、TBB | 1P1C ns / 多P多C 吞吐 |
| **Mutex/CV** | Go sync、futex、folly | 无竞争 ns / 竞争公平性 |
| **网络（TCP/UDP）** | muduo、libevent、asio、Seastar | 吞吐 / p99 / 连接数 |
| **HTTP/WS** | nginx、Drogon、Gin、uWebSockets | req/s / 延迟 |
| **缓存** | Caffeine、Ristretto、groupcache | 命中率 / Mops |
| **序列化** | Protobuf、FlatBuffers、Cap'n Proto | ns/字段 / 兼容性 |
| **P2P** | libnice、Pion、coturn | 穿透率 / 延迟 |
| **媒体** | libwebrtc、FFmpeg、GStreamer | 延迟 / 压缩率 / CPU |
| **调度器** | Go runtime、Tokio、Seastar | ns/task |
| **应用框架** | GoFrame、Gin、Drogon | 路由 ns / 中间件 |

## 五、交付检查（每个大模块）

```
□ 有 vs-<module>.md（对比矩阵，含工业库数字）
□ 代码量 ≤ 2000 行，接口 ≤ 15 方法
□ 功能覆盖 ≥ 80%（缺的写理由）
□ 性能 ≥ 工业库 80%（并发 ≥ Go 90%）
□ 边界（异常/超时/取消/背压/断开）全处理
□ 测试 ≥ 5 真实场景 + 压测 ≥1e7 + ASan/UBSan
□ 汇编级证据（objdump 指令/分配 + 物理下限几倍）
```
