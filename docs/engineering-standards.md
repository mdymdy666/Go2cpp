# 工程标准（Go2Cpp）

> 本文件是项目级强制规范。与 `docs/reports/asm-*.md`（性能审查）配合使用。

## 一、对标工业级实现（强制）

**所有实现必须对标工业级实现**——不是「能跑就行」，而是「和这个领域最强的库比」。

### 1.1 实现前：先调研（**先查项目内，再查项目外**）

**第一步：查项目内是否已有实现——不许重复造轮子。**

每个新功能动工前，按顺序查一遍：

1. **docs/ 下的模块文档**——很多依赖/路径/编译方式已经写死在那里。
   - 例：docs/quic.md 写明 picoquic 在 ~/build-deps/picoquic（1.1.53.0），
     结果 2026-11-02 仍有人自研 QUIC 570 行、又重复编译一份。
   - 例：docs/modules/storage-*.md 写明 LevelDB 的引入方式与限制。
2. **xample/ 与 xamples/**——已有示例就是最直接的用法参考
   （xample/app/ 7 个 HTTP/WS/流/缓存/P2P 示例，xamples/ 5 个媒体/传输示例）。
3. **grep 全仓**（同名函数/类/模块/常量）——可能已经有 80% 的实现。
4. **docs/reports/reuse-audit.md**（复用审查）——已登记的 15 组真重复，
   动工前先看自己的模块是否撞上。
5. **AI_COLLAB.md**（协作记录）——同一天其他 agent/人已经做了什么。

**第二步：查项目外的工业库**（见 §四参考清单）。

- 记录：它怎么做（架构/算法/数据结构）、性能数据、边界处理；
- **能复用就复用**（项目内已有 > 工业库 > 自己写）；
- **能移植就移植**（不许凭印象说「没有成熟方案」）；
- **禁止**：不问不查就新写一份；**尤其禁止**把已有实现「复制进自己的模块」
  （这正是 2026-11-02 复用审查里 crc32_x86.hpp 的问题——为了不改一行 CMake，
  把 21 GB/s 的 CRC 抄进 compress）。

**教训（写进流程，不是写进检讨）**：2026-11-02 一天内发生了 3 次「重复造轮子」——
picoquic 重复自研、LevelDB 重复编译、CRC 重复实现。三次都是「没先查项目内」。

### 1.2 实现后：必须对比

每个大模块完成后，**必须产出对比矩阵**（写进 `docs/reports/vs-<module>.md`）：

| 维度 | Go2Cpp | 工业库（名字/版本） | 结论 |
|---|---|---|---|
| **性能**（吞吐/延迟/内存） | 实测数字 | 官方/论文数据 | 几倍/持平/领先 |
| **功能**（覆盖度） | 支持哪些 | 支持哪些 | 缺什么 |
| **边界**（异常/极限） | 怎么处理 | 怎么处理 | 差在哪 |
| **API**（易用性） | 签名/语义 | 签名/语义 | 是否对齐 |
| **代码量**（简洁度） | 行数 | 行数 | 是否更简单 |

**禁止**：只写「我们很快」而不给工业库对照数字。

## 二、要求简单（强制）

**简洁 > 复杂**。工业级不等于「代码多」，而是「用最简单的方式达到最强」。

### 2.1 简洁准则

- **单文件/单职责**：一个模块一个 .hpp + 一个 .cpp；
- **能用标准库就不自造**（`std::` 优先，除非有明确性能理由）；
- **接口最小化**（YAGNI）——只暴露调用方需要的；
- **无过度设计**：不预先抽象「将来可能用」的东西；
- **无炫技**：不用模板元编程/宏魔法，除非收益明确；
- **注释写「为什么」不写「是什么」**。

### 2.2 反例（不许出现）

```
❌ 500 行的「通用」工厂，实际只用了 1 个实现
❌ 为了「可扩展」引入 3 层虚接口
❌ 用 template 元编程算一个编译期常量
❌ 每个类都套 shared_ptr + pimpl（无必要）
```

### 2.3 度量

- **每个模块 ≤ 2000 行**（超过要拆分或说明理由）；
- **每个公共接口 ≤ 15 个方法**（超过要反思）；
- **编译时间**：单模块 ≤ 5 秒（超过要查模板/头文件膨胀）。

## 三、尽量全面强（强制）

- **功能覆盖**：工业库有的核心功能，我们至少覆盖 80%（缺的写清理由）；
- **性能**：数据面 ≥ 工业库的 80%（并发原语 ≥ Go 的 90%）；
- **边界**：异常/超时/取消/背压/断开——每个都要处理（不许「假设不会发生」）；
- **测试**：每个模块 ≥ 5 真实场景 + 压测 ≥1e7 + ASan/UBSan。

```

□ 功能覆盖 ≥ 80%（缺的写理由）
□ 性能 ≥ 工业库 80%（并发 ≥ Go 90%）
□ 边界（异常/超时/取消/背压/断开）全处理
□ 测试 ≥ 5 真实场景 + 压测 ≥1e7 + ASan/UBSan
□ 汇编级证据（objdump 指令/分配 + 物理下限几倍）
```

## 优化顺序：架构优化 > 汇编优化

**先架构，后汇编。**

| 顺序 | 类型 | 收益量级 | 实例 |
|---|---|---|---|
| **第一** | **架构**（锁/所有权/数据结构/算法/并发模型） | **数量级** | Link 收发分离：p99 1405ms→0.045ms（3.1 万倍）；per-P runnable：wall -24% |
| 第二 | 汇编（指令/内联/分配） | 百分点 | enqueue 709→595 指令（-16%）；栈帧 696→104B（-85%） |

**判断**：锁/所有权/数据结构还有问题 → 先改架构；架构 OK → 再汇编。
**禁止**：只做汇编不做架构。
